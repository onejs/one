# DOM component runtime

The native transform calls `createDOMComponent(stableId)` from `one/dom/native`. A browser entry calls `mountDOMComponent(Component, stableId)` from `one/dom/client`. Ordinary web imports render the original component with the existing SSR rules. `one/dom` exports `DOMProps`, the supported data and action types, and `useDOMImperativeHandle(ref, factory, deps)`. Imperative methods return promises on both platforms. The hook supports one handle per hosted component and reserves the method name `then`. Factory dependency changes replace the committed method table without rejecting already running calls. Retained handles dispatch new calls to the latest committed methods; removed methods reject new calls while their already running calls may finish. Unmount or document disposal rejects outstanding calls.

The component's optional `dom` prop configures the native container: style, scrollEnabled, matchContents, onLoad and onError. Container options never enter component data. onLoad reports the host document's completion; the imperative ref becomes available when the browser hook commits. matchContents applies the measured browser height at the native container's width. Providers, router state, native modules, children and React elements cannot cross this boundary. Navigation that needs native behavior uses an explicit parent callback action.

Host load errors and browser process termination invalidate the document and reject its outstanding calls. Errors reach `dom.onError` when supplied; otherwise the proxy logs the error detail without throwing from the native event callback. Recovery starts a fresh document and ref. A valid browser `error` message can arrive before `ready`, retaining its serialized name, message and optional code and development stack. Reporting that error leaves the peer waiting for readiness, so a recovered entry can still mount. Other pre-ready messages retain their normal protocol checks.

`protocol.ts` defines the shared versioned wire contract. Values are finite numbers, strings, booleans, null, arrays and plain objects. Undefined object fields are omitted recursively, including optional top-level props. Array holes and undefined entries, nested functions, classes, Date, Error, symbols, BigInt and cycles are rejected with paths. Only top-level function props become actions. Value, void and error responses are distinct. Error stacks travel only in development.

`DOMNativeBridge.prepare` produces a prospective native bootstrap snapshot without changing the committed callback table. A layout effect commits the snapshot and latest handlers. Unchanged data and action names send no state messages even when handlers change. Each native document starts a separate peer, epoch and pending map. A ready message carries its captured revision; later committed revisions reconcile in order. Old epochs are ignored, reused native epochs are rejected, and malformed messages invalidate the peer before dispatch. Disposal rejects pending calls once and suppresses replies from actions that finish after disposal.

## Native host seam

`OneDOMHostNativeComponent.ts` defines the Fabric host. Props are entryId, developmentURL, bootstrapState, scrollEnabled and ViewProps. Its only command is ordered `post(ref, JSONString)`. Events carry document start with epoch/revision, message, document completion, errors and process termination. A revision is a nonnegative JavaScript safe integer.

For every new document, native captures its latest committed bootstrapState `{version,revision,props,actions}`, assigns a unique epoch across instances and documents, adds entryId and os (`ios` or `android`), and injects `globalThis.__oneDOM` before application scripts. The shim exposes `bootstrap`, `postMessage(string)` and `subscribe(listener):unsubscribe`. It queues writes until the platform transport is available. Native enqueues onDocumentStart before any page events from that document. Updating bootstrapState never recreates a page. Updates committed after the capture reconcile after ready; document-start does not promise globally latest props without a round trip.

The native shim reports window errors and unhandled rejections from document start through the first transport subscription using the same versioned `error` envelope. The first subscription removes those early listeners as the browser client takes over reporting. Script and stylesheet load failures must retain the failing resource URL. Stacks are omitted from production documents.

Native owns main-frame and origin checks, action/navigation policy, selected immutable production build/update resource identity, asset root, process recovery and platform availability. It must dispose the browser while its realm is alive, through a versioned dispose message or pagehide. Native teardown and process death release old document resources; recovery captures a fresh committed snapshot and epoch. Commands and replies cannot be delivered across views or epochs. Development uses the existing dev-server origin at `/_one/dom/<id>/`; production looks up a stable ID in the selected protocolVersion 1 manifest.

The browser HTML provides `#one-dom-root` with natural height, `display:flow-root`, `width:100%`, `min-width:0` and body margin zero. ResizeObserver schedules one measurement per animation frame; rounded finite sizes suppress unchanged reports. Browser disposal removes its sole transport subscription, global listeners, observer and animation frame.

The focused JavaScript probes cover serialization, callbacks, document races and React commit ordering with a simulated host. Native transport, owned resource loading, navigation checks, device layout/keyboard behavior and performance require independent native and device validation.

The native host source is `host.native.tsx`; `one/dom/native` selects its native build. A bare `native.tsx` filename collides with the package builder platform suffix recognition and loses its ESM output.
