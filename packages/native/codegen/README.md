# SwiftUI generation plan

## Baseline before SDK derivation

`Extract.swift` parses the SDK's SwiftUI, SwiftUICore, and framework overlay interfaces into declarations. `inventory.ts` normalizes them and checks availability. The generator then selects only names and signatures written in `catalog.ts`, `controlCatalog.ts`, `leafCatalog.ts`, `emitContainers.ts`, `emitSheet.ts`, and `emitPopover.ts`. A new view needs a constructor recipe, fields, a React adapter, a Fabric spec, and Swift hosting code. A new modifier needs a catalog selector, a transport field in a control or container, a TypeScript prop, and a Swift call. `swiftStyle` also needs a field, its native conversion, and an application call. The manifest reports declarations that are still unmapped; it does not bind them. `One.iOS` spreads `Swift`, so an emitted `Swift` member reaches both namespaces once exported. The generic leaf derivation introduced in `bf6713036` and wired in `2f766e892` derives Swift calls only after a person writes a leaf recipe. Coverage introduced in `d10d7834a` measures the gap but does not close it.

## Plan

1. Read public `View` methods and public view types from the SDK inventory. Classify parameters by the types the React Native bridge can represent directly: booleans, numbers, strings, and SDK enum values. Generate prop types, defaults, native conversion, and Swift application from those declarations. Prefer one SDK-selected signature per prop and fail on ambiguous overloads. Keep the iOS availability gate in generated Swift and the version metadata in the manifest.
2. Keep explicit overrides only for semantics absent from a signature: bindings and events, generic construction, view-building closures and slots, layout ownership, and values such as `Color` needing conversion. List each override category and its files below. `tabViewBottomAccessory` uses a view-building slot; its placement is an SDK environment value that accessory content can read.
3. Regenerate, typecheck, build a native consumer, and render an accessory plus two newly derived modifiers in an iOS 27 simulator. Record modifier counts before and after. Check generation for drift and run the native tests covering the touched interfaces.

## Semantic overrides

- Closures and bindings: `controlCatalog.ts`, `leafCatalog.ts`, and `controlTypes.ts` choose React events, controlled values, actions, and constructors with label or content closures. A Swift closure signature does not say which state React owns or when an event fires.
- View builders: `emitContainers.ts`, `emitSheet.ts`, and `emitPopover.ts` map React children to SwiftUI slots and own layout, presentation, and dismissal. Single-child `View` modifier names, parameter labels, required SDK enum, string, and Boolean arguments, Boolean bindings, and Swift calls are generated from the SDK. Hashable generic bindings beside a child builder specialize to strings. Direct generic `View` arguments use the same child slot when there is no builder overload. Distinct enum argument types and direct argument labels give overloaded slots distinct prop names. `Swift.ViewSlot` applies these names to a base view using one `ViewSlot.Content` child and typed `options` when required. Binding options carry a value and `onChange` through the existing named native event shape. `Tabs.native.tsx` also accepts `Swift.TabViewSlot` with a generated tab modifier name and explicit content height; `OneNativeTabsView.swift` mounts the slot content. `TabViewBottomAccessory` still chooses inline versus expanded content from its placement environment. `emitContainers.ts` also declares the `NavigationStack` and `Toolbar` family: the stack hosts React Native children through a dedicated inline content child and reads `Toolbar` markers as SwiftUI `ToolbarContent`, and the three toolbar markers are one Swift view configured by kind.
- TabContent builders: `emitContainers.ts` declares `OneNativeTabs` with `swiftStyle`, so scalar TabView modifiers (`tabBarMinimizeBehavior`, `tabViewSearchActivation`, `defaultTabBarPlacement`) come from the SDK. `Tab` and `TabSection` are `TabContent`, which the `View` modifier derivation does not cover: `Tabs.native.tsx` validates their modifiers against the generated enums and sends them as one `tabModifiers` JSON prop per `OneNativeTab`, and `OneNativeTabsView.swift` applies each with its SwiftUI availability. `sectionActions` are native SwiftUI buttons that dispatch `onNativeTabsAction`.
- Generics and non-scalar values: `catalog.ts` supplies menu tree payloads, style conversions such as `Color` and `ShapeStyle`, and framework imports. Generic constraints do not identify the concrete React value or native conversion.
- Handwritten native hosts: `catalog.ts` retains `OneSwiftHost` and the two `OneNativeArrangement` hosts in the Fabric component provider map because they have no SwiftUI SDK view declarations.

SDK signatures cannot choose a React Native layout model or what React children feed a `@ViewBuilder`. These stay explicit. Scalar, URL, enum, callback, and binding modifier names and argument types come from the SDK. Cases and static or class values imported through Objective-C or other frameworks come from their public SDK symbol graphs, cached per SDK version. Multiple bridgeable arguments use one generated object prop and an ordered native payload, including text lists and string sets. Required bridgeable arguments can use SDK defaults for other arguments. Generic and opaque protocols use their SDK `Self == ConcreteType` cases to generate literal props and Swift calls; concrete overloads keep their public prop name. A public `RawRepresentable` type with a string `rawValue` initializer generates a string prop and native constructor. A modifier whose non-closure arguments all have SDK defaults generates a boolean prop when the argument types cannot be bridged. A single `Hashable` or `Equatable` value uses a string specialization; existing non-generic overloads keep their public prop names. Callback modifiers dispatch a named native event, including single and paired SDK enum values. Frozen enums with associated bridgeable scalars or points produce a typed case and value payload. Bindings carry a controlled value and `onChange` callback through the same event path.

Public zero-argument `View` methods without generic requirements are derived as boolean enable props. This adds 17 names, including `hidden`, `labelsHidden`, and `compositingGroup`, with availability checks and framework imports for overlay methods. Callback and `Binding<Bool|String>` signatures with defaulted other parameters use one generated event transport. The same transport carries typed scalar callback values such as `onHover`. View builder slots with one content closure and any number of defaulted other parameters use one generated slot application method. Labeled scalar arguments, `Text` values, optional values, SDK enum cases, and framework overlay modifiers also derive from shared conversion rules. Optional values preserve an explicit `null` separately from an absent prop. More complex closure shapes, non-scalar bindings, layout rules for other ViewBuilder families, and generic constraints still need a hand mapping. Zero-argument async actions on `task` and `refreshable` now emit an action identifier and await its JavaScript callback through one native completion registry. Async closures with one public SDK struct input now project its bridgeable fields and await the JavaScript callback; `onInAppPurchaseStart` supplies the product ID, type, name, description, price text, and family-sharing flag. Other async input and result shapes still need value conversion.

## Result

The iOS 27 SDK inventory now supplies parameterless public views, unambiguous scalar and enum `View` modifiers, bridgeable callbacks and bindings, and single-child view-builder slots. The generator emits their React props or slot names, native transport, Swift calls, and availability metadata. Derived style modifiers use one JSON field in the existing `swiftStyle` Fabric struct, so adding an SDK modifier does not add a C++ prop to every generated host. Swift applies only modifiers present in that field, in prop order.

Codable native object bindings now round trip opaque JSON strings through native change events. `tabViewCustomization` uses this path; a null initial value creates its public default customization, and the app can persist a value emitted by native code and pass it back. Other native object bindings without public Codable conformance still need a value mapping. Generic `Transferable` value and array signatures specialize to strings: `draggable` accepts one string, `copyable` accepts a string array, and `pasteDestination` emits received strings. `cuttable` uses the same string specialization: native returns the configured array on a cut and emits `onAction` so React can update its state. Transferable models other than strings still need an app-defined representation. A Boolean predicate closure or Foundation `Predicate<Input>` can use a constant decision, so `mapFeatureSelectionDisabled` applies the same setting to every feature and `fileDialogURLEnabled` allows or rejects every URL; per-item selection needs a richer mapping. A closure returning a numeric scalar can use a configured constant; both horizontal and vertical `alignmentGuide` overloads now derive from their SDK alignment cases and finite numeric values. Dimension-dependent guides still need an expression mapping. Boolean bindings and URL result callbacks can now appear beside scalar record arguments, with each nested event routed by its SDK parameter name. `fileMover` accepts a controlled presentation Boolean and source URL, then returns a success URL or failure description through its completion callback. The same generated record path accepts an optional URL binding and optional URL result callback for `photosReferenceImageViewer`. A generic `Transferable` item with a URL result specializes to `String`, deriving `fileExporter` without a separate file API recipe. A public point initializer and point getter on a bound SDK value derive a controlled point transport; `webViewScrollPosition` now sends and receives finite coordinates through the WebView host. Other ScrollPosition modes, such as view IDs and edges, need value mappings. Event callbacks now project public fields whose values are bridgeable, leaving opaque SDK fields out of the payload. `onDropSessionUpdated` exposes count, suggested operation bits, size, and location. Existing no-argument callbacks keep their prop names when a richer event overload appears; the richer `onMapCameraChange` overload gains a named alias. A callback that returns a public SDK enum or a struct with one enum constructor now accepts a selected result and a typed action callback; `onKeyPress` returns `handled` or `ignored`, and `dropConfiguration` returns a selected drop operation while exposing its public session fields. Public class properties and open enum cases from a framework symbol graph now use the same event projection; `onCameraCaptureEvent` emits its capture phase and an `unknown` case for future SDK values. A scalar argument and projected class callback use one generated record, so `onContinueUserActivity` supplies an activity type and receives public activity fields. SDK callbacks named `update` instead apply a generated object of public writable scalar fields in Swift; `userActivity` uses this to configure the native activity. A transferable string array paired with a public SDK session also uses the structured event transport, so `dropDestination` emits received strings and its session fields. A closure returning `NSItemProvider` can derive a string payload through Foundation’s public provider initializer; `onDrag` and `itemProvider` use this one conversion. Public `Gesture` structs with default constructors and bridgeable end values now supply the same six gesture options to `gesture`, `highPriorityGesture`, and `simultaneousGesture`. Each option emits its typed end value through the native event path. This derives `translationPresentation` and richer overloads for `dialogSuppressionToggle` and `manageSubscriptionsSheet` while preserving their existing simple prop names. Image arguments currently accept SF Symbol names through the public `Image(systemName:)` constructor; asset-backed images need a separate source mapping. Parameterized view closures can use a static React child slot when the native closure input is not needed; the SDK now supplies `documentBrowserContextMenu` and `subscriptionStoreControlIcon` this way. Supporting SDK modules such as CoreText supply argument cases without changing the SwiftUI modifier denominator; `lineHeight` comes from its static values. A public scalar initializer can wrap a generated value, so `dragConfiguration` uses its `allowMove` Boolean constructor. A unique public constructor path can also build a value from one string input and public default or empty arguments. This maps a shader function name through `ShaderFunction` and `Shader`, supplying `colorEffect`, `distortionEffect`, and `layerEffect`; the latter two also bridge `CGSize` from finite width and height fields. The app must provide a Metal function with the chosen name in its default shader library. Public static factories with one string input also derive value construction; StoreKit’s `subscriptionBundle` factory now supplies the `kind` argument of `appStoreMerchandising` beside its Boolean presentation binding. Public typealiases also preserve SDK value types: `StoreKit.Transaction.ID` resolves to `UInt64`, so `refundRequestSheet` accepts a decimal string without losing digits in JavaScript and emits its presentation binding changes. App Intents supplies the public failable activity identifier constructor, so `appEntityIdentifier` accepts a serialized activity identifier string or null and rejects an invalid string. Generic modifiers constrained by both a value protocol and a marker protocol derive cases from the value protocol and filter them by public conformance. `symbolEffect` now accepts the seven indefinite effects in the Symbols SDK; its default options and active state come from the SDK signature. Public writable Boolean fields on an inout struct also generate an update record: `transaction` accepts `isContinuous`, `disablesAnimations`, `tracksVelocity`, and `scrollPositionUpdatePreservesVelocity`, each guarded by its SDK availability. Other transaction values still need conversions. Public `PreferenceKey` types with a bridgeable `Value` alias now derive set, transform, and change callbacks from their SDK signatures. `PreferredColorSchemeKey` supplies all three through its optional color scheme values. Async `View` actions with no inputs generate promise-returning React callbacks; SwiftUI awaits their completion, and task cancellation releases the native continuation. Async callbacks carrying a public value and `Result` now use the same path. The generated `onInAppPurchaseCompletion` payload includes the product, purchase result cases, verification status, signed transaction JWS, and errors; JavaScript completion releases SwiftUI only after its promise settles.

The raw 522-name denominator includes SDK methods whose required inputs expose no public iOS value. For example, `scrollInputBehavior` requires `ScrollInputKind`, but every public case and factory for that type in the iOS 27 interface is unavailable on iOS. Those names cannot become working iOS props by generating a call from the public interface alone.

Bridgeable overloads get distinct prop names from their parameter labels or types while retaining the SDK method name in Swift. For example, `onOpenURLWithPerform` and `onOpenURLWithPrefersInApp` expose two SDK `onOpenURL` calls. A generated name without a working native call does not count.

`bold` and `tracking` are two previously unmapped modifiers exercised by `tests/native-features/app/one-native-autogen.tsx`. `tabViewBottomAccessory` now uses the generated slot call while its inline and expanded React content keep the placement environment mapping. The iOS 27 simulator proof shows expanded and inline placements. Native iOS CI now uses the Xcode 27 runner image, and `generate.ts` accepts iOS 27 symbols into checked-in bindings.
