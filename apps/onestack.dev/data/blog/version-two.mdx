<IntroParagraph>
  One v2 brings native platform components and services into the same package as
  the router. It also moves the default bundler to Rolldown, adds a native
  project generator that works without Expo, and updates navigation to React
  Navigation 8 alphas. The beta includes the routing, data loading, web rendering,
  and deployment work from the v1 line through 1.27.
</IntroParagraph>

One is a React framework for web, iOS, and Android. You configure a Vite plugin,
write file-system routes, and choose how each web page renders. Native routes
run in React Native. That structure stays the same in v2; the new work gives
you more of the platform underneath it.

You can try the beta with:

```bash
npx one@beta
```

This is a beta. The native interfaces require the New Architecture, and the
navigation packages are alpha versions. Check the requirements and your native
dependencies before upgrading an existing app.

## One Native

One Native ships inside `one`. You can use SwiftUI components through
`One.iOS`, Jetpack Compose components through `One.Android`, and shared
components through `One.UI`. You can keep using React Native views alongside
them.

On iOS, the components cover the parts of a screen you would normally build in
SwiftUI: stacks and grids, lists and forms, buttons and toggles, text fields
and editors, pickers, progress indicators, shapes, sheets, popovers, menus,
and tabs. There are bindings for maps, photo picking, video and Live Photo
playback, web views, sharing, and Quick Look. `Glass` and
`GlassEffectContainer` expose Liquid Glass on supported iOS versions.

The iOS bindings are generated from the SDK with explicit mappings for props,
child slots, and events. Native hosts carry React Native content into SwiftUI
containers, and the layout boundary determines which system sizes the content.
`swiftStyle` configures native appearance and modifiers; React Native `style`
positions the host in its surrounding layout.

On Android, Compose covers rows, columns, wrapping layouts, cards, surfaces,
text, icons, buttons and floating action buttons, switches, checkboxes, radio
buttons, text fields, sliders, segmented controls, chips, badges, list items,
dialogs, and progress and loading indicators. These use Android's Material
controls and theme defaults. The Android surface has its own props and layout
rules; it does not translate a SwiftUI screen into Compose.

Shared components include `Image`, `Map`, `Icon`, `TextInput`, `EdgeFade`,
`Blur`, `Mask`, safe areas, and Picture in Picture. `Icon` accepts an element
for each platform and a semantic color role or explicit color. `useNativeState`
is a named import from `one`; it creates an observable value that native
controls can share. Native edits update that store directly, and React
subscribers receive the updated value.

Native tabs have two separate uses. The router's `Tabs` connects file routes to
React Navigation. `One.iOS.Tabs` and `One.iOS.Tab` let you compose a SwiftUI
`TabView` directly, including sections, badges, action tabs, and supported
accessory slots. Likewise, `One.iOS.NavigationStack` and its toolbar components
are available for explicit native composition alongside the routed `Stack`.

The [One Native guide](/docs/native-overview) explains setup and platform
boundaries. The [component references](/docs/native-components) link to the
individual APIs.

## Native services

The package now includes services you previously had to assemble from separate
native dependencies. Shared namespaces cover notifications, clipboard,
connection state, haptics, browser and authentication sessions, image and
document picking, secure storage, speech recognition, SQLite, app information,
launch-screen control, and over-the-air updates. `One.Auth.Apple` provides
Apple authentication. `One.openURL`, `One.openShare`, and `One.openSettings`
open the corresponding system surfaces. Native `fetch` supports streaming
responses and React Native file parts in `FormData`; the global `crypto`
provides secure random values and UUIDs.

There is also a larger iOS-only surface: foreground and configured background
location, geocoding, MapKit search and directions, sandbox files, audio playback
and recording, camera preview and code scanning, Photos assets and albums,
image transformations, contacts, calendar events and reminders, localization
and device information, motion sensors, orientation, screen capture,
preferences, protected Keychain storage, purchases, and system review and
print requests. Background tasks, device attestation, alternate app icons,
tracking permission, keep-awake control, and Home Screen quick actions are
available through `One.iOS` too.

Each service has its own permission and platform requirements. Some depend on
hardware, signing capabilities, a configured account, or an OS decision to show
a system surface. An exported API is not a guarantee that a simulator can
exercise all of it. The [platform API guide](/docs/native-apis) links to the
contracts and their limits.

Widgets and Live Activities use a generated WidgetKit extension. You can write
a typed payload or a JSX layout built from `One.iOS.WidgetUI`; the extension
renders it in SwiftUI without starting the app's JavaScript. The generated
extension, App Group, and signing capabilities need to be configured before
these calls can work.

## Native projects with or without Expo

For an app without Expo, `one prebuild` generates iOS and Android projects
from `native.app` in `vite.config.ts`. The manifest holds the app name,
identifiers, icons, launch screens, fonts, orientation, appearance, links,
permissions, entitlements, and platform build settings. There is no Expo app
config or config plugin on that path.

Apps that install Expo keep using Expo prebuild with `vxrn/expo-plugin`.
That adapter connects the generated project to One while preserving Expo
modules and config plugins. `one run:ios` and `one run:android` launch the
native projects against your running One development server.

You can also import Swift and Kotlin source from application code. One derives
a typed contract for supported native functions and generates the glue used by
the native build. Swift packages can expose native views. Editing native source
still requires rebuilding the native binary; JavaScript hot reload cannot
replace compiled Swift or Kotlin.

Environment variables use `ONE_PUBLIC_` by default. `EXPO_PUBLIC_` remains
supported for Expo dependencies. A `ONE_PUBLIC_X` value is available as
`EXPO_PUBLIC_X` when that name has not already been defined; an explicit Expo
value keeps its own value. See [environment](/docs/environment) and
[native setup](/docs/native-setup).

## Rolldown and Metro

The default native bundler now uses Rolldown for both development and production.
Development supports React Refresh and incremental updates. The default
transform pipeline uses Oxc and the native Worklets transform, and can bundle
supported imports into worklet runtimes. The web build also uses Vite 8 and
Rolldown.

[Metro mode](/docs/metro-mode) remains available for apps whose dependencies
need it. `one/babel-preset` and `one/metro-config` share One's configuration
with Metro, and `one metro-eject` lets an app own those files. Configuration
and lockfile changes invalidate Metro's cache.

Production asset serving gained precompressed Brotli, Zstandard, and gzip
files, with freshness checks against the source asset. Native updates can use
One's own update service or the integrations described in the
[OTA guide](/docs/guides-ota-updates). `One.Updates` checks, downloads, stages,
and reloads bundles. The native launcher handles early-failure rollback and
cache pruning; choosing and hosting an update is still the application's
responsibility.

## Routing and navigation

The routing work since the v1 release candidate is included: typed paths and links, nested
layouts and groups, platform-specific route files, protected routes, route
validation, navigation blocking, and route masks. You can display a short URL
while navigating to a more detailed route, or preserve a scroll position while
moving between child pages.

React Navigation 8 alphas are the basis of v2 navigation. Web navigators have
headless renderers, and `Presentations` composes their output. The web path
keeps React Native out of its module graph. `Stack.Header` and `Stack.Toolbar`
provide declarative native header and toolbar composition. `Tabs.Protected`
adds guards to tab routes, and route loading can suspend on native and web.

`getLinking` exposes the linking configuration, and `useSitemap` reads the route
tree. Deep-link handling includes nested routes and cold launches.
[Environment guard imports](/docs/configuration#environmentguards), such as
`server-only` and `native-only`, catch modules imported into the wrong build.

## Data loading

[Typed loaders](/docs/routing-loader) run with the route's params and request
context, and their results flow into `useLoader`. Refetching and
`useLoaderState` cover changes after the first load. `useMatches`, `useMatch`,
and `usePageMatch` give layouts access to matched routes and their data;
`useSearchParams` provides the familiar URLSearchParams interface.

`loaderCache` deduplicates concurrent server loader calls and optionally keeps
results for a configured TTL. During development, `watchFile` lets a loader
track a local content file and refresh when it changes. Loaders can validate
params and redirect. Middleware supplies shared request context, and
`setServerData` and `getServerData` pass server data into rendering.
`setResponseHeaders` sets cache headers, cookies, and other response metadata.
Headless server loaders can run without a built route map.

## Web rendering and deployment

You can still choose SSG, SSR, or SPA globally or per route, and mix them in the
same app. Root layout render modes and SPA shell rendering let the initial
HTML include shared navigation, head tags, and CSS while page content loads
on the client. Static generation uses worker threads to render pages in
parallel.

The web work includes layout CSS inlining, improved CSS collection during
navigation, configurable script loading, intent-based link prefetching, and
`?imagedata` imports for image dimensions and blur placeholders. Skew protection
handles deployments where an open page and the server have different builds,
including an optional proactive check and retries for transient module loads.
Sitemaps support per-route overrides.

[Deployment](/docs/guides-deployment) targets include Vercel and Cloudflare
Workers. Cloudflare builds use its Vite plugin, merge the app's Wrangler
configuration, load modules lazily, and expose the worker environment and
execution context to API handlers. The output stays an ordinary build
artifact you can host yourself.

## Development tools

The [DevTools panel](/docs/dev-tools) brings together route inspection, loader
timing, SEO preview, error reporting, and a source inspector. Source inspection
includes an element picker and input recording. MDX content participates in
loader hot reload and supports smart typography.

Route warming and dependency tracking reduce repeated startup work. Web-only
apps can set `native: false`, and React Compiler configuration is available
through the plugin. The CLI also includes a daemon for managing development
across multiple apps. These changes support the same development loop: edit a
route or its data, see the result, and inspect the code that produced it.

## Upgrading

The v2 package requires React 19.2.3 or later within React 19 and React Native
0.87, with 0.87.1 used by the current native examples. Native views require the
New Architecture. The package's iOS deployment floor is 17; newer APIs have
separate runtime requirements, including iOS 26 for Liquid Glass. Align your
React Navigation dependencies with One's 8 alpha peers rather than mixing
navigation versions.

Start with the [installation guide](/docs/installation), then read
[native setup](/docs/native-setup) and the
[platform notes](/docs/native-platforms) for the APIs your app uses. For the
individual fixes and releases behind this post, see the
[release history](https://github.com/onejs/one/releases).
