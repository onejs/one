<IntroParagraph>
  The v2 beta line is available on the npm `beta` dist-tag. It collects
  everything since the v1 beta: the v1 stable line through 1.27, a new native
  interface library, React Navigation 8 alphas, a zero-Expo native toolchain,
  and a reworked native bundling pipeline. This post summarizes the changes as recorded in git history and the
  per-release notes.
</IntroParagraph>

Install the beta with:

```bash
npx one@beta
```

## One native

One native is a library of real platform interfaces for React Native apps,
shipped inside the `one` package. The iOS surface is generated
SwiftUI, exposed through a `Swift` export and as `One.iOS` in app code: tabs,
menus, pickers, form controls, sheets, full screen covers, containers,
popovers, video, maps, web views, sharing, the photo library, empty states,
and Quick Look. The Android surface is Jetpack Compose, exposed through a
`Compose` export and as `One.Android`, backed by a
`OneNativeComposeNodeManager`.

The bindings are generated from the platform SDKs rather than handwritten. The
generator reads the SwiftUI overlay modules and emits Fabric components with
shared native state: controls and sheets, buttons, indicators, text input with
focus and keyboard type, alerts and confirmation dialogs, menus and tabs, text
and labels with nested SwiftUI containers, popovers with composed triggers, and
hosting and presentation hosts that carry a React Native subtree into a
SwiftUI container. Later additions include Map, QuickLook, VideoPlayer, an
Image binding, action tabs, Liquid Glass and Material surfaces, stacks,
spacers, labeled content, slider labels, and a `swiftStyle` styling surface.

Shared cross-platform primitives live under `One.UI`: `EdgeFade`, `Blur`,
`Mask`, `Icon`, `TextInput`, `useNativeState`, and `SafeArea`.
`One.UI.Icon` takes one element per platform (`icons.ios` as `One.iOS.Image`,
`icons.android` as `One.Android.Icon`, optional `icons.web`) and a single
color source: `colorRole` with `primary`, `secondary`, `tertiary`, `accent`,
or `danger`, resolved by the active native color scheme, or a React Native
`ColorValue` `color`, including iOS dynamic colors. The role defaults to
`primary` when neither prop is present. `TextInput` and `useNativeState`
share one observable store between JavaScript and the bound SwiftUI and
Compose views, so keystrokes land without a React render.

Native tabs come in two layers. The file router's `Tabs` stays on React
Navigation native tabs. `Swift.Tabs` with `Swift.Tab` children is a separate
low-level `TabView` for explicit composition: controlled `selection` with
`onSelectionChange`, badges, roles, and action tabs that carry `onPress`
instead of a page.

During development the library lived in a separate `one-native` workspace
package. It was folded into `one`, so consumers install and import
one package. The fold raised the floor for the whole package: React Native
0.87 with the New Architecture, since the library ships Fabric components.
The iOS floor stays at 17, with iOS 26 features gated at runtime.

See [native docs](/native) and the
[iOS native guide](/docs/guides-ios-native).

## Native toolchain

Native projects no longer go through Expo tooling. `one prebuild` generates
the iOS and Android projects from the validated `native.app` manifest in
`vite.config.ts`: app icons and launch screens from shared sources, bundle
ids, and deployment settings in one code path, with no Expo app config or
config plugin. `one run:ios` and `one run:android` launch through the React
Native community CLI against the running dev server. Bundler selection is
explicit: the Rolldown pipeline is the default, Metro mode stays available.

Expo compatibility is optional. Expo modules keep working where projects
install them, and the environment contract accepts both prefixes:
`ONE_PUBLIC_` is the default naming convention, `EXPO_PUBLIC_` stays fully
supported, and a `ONE_PUBLIC_X` value is also exposed as `EXPO_PUBLIC_X`
when that Expo variable is absent. An explicitly defined Expo variable keeps
its own value, and Expo variables never create `ONE_PUBLIC_` names. See
[environment](/docs/environment).

## Native bundling

The default native bundle pipeline is now rolldown based. `rolldown dev()`
renders on the iOS simulator with React Refresh HMR, incremental patches on
file change, and full reload fallback, and production native bundles build
through rolldown as well. Native transforms moved to Babel-free Oxc and
Rolldown transforms, with selected pure imports bundled for worklet runtimes.

Around that pipeline: support for React Native 0.87, a real EXUpdates
manifest for project-local assets, precompressed `.br`/`.zst`/`.gz` siblings
served with an mtime guard, and static asset cache headers through
`server.cacheControl`. Metro mode stays available with shared config through
`one/babel-preset` and `one/metro-config`, `one metro-eject` for opting out of
CI auto-generation, automatic cache clearing on config and lockfile changes,
and `process.env` support in the babel plugin. See
[Metro mode](/docs/metro-mode).

## Navigation

One moved to React Navigation 8 alphas. `Presentations` replaces
`NavigationRender`, and Stack, Tabs, and Drawer render through pluggable web
rendering with headless web navigators, so `react-native` stays out of the
web module graph. The Stack gained a header composition API with child
processing, and the router added toolbar support, suspense, protected
redirects, `Tabs.Protected`, an option to suspend on route load for native
and web, deep linking config with a `getLinking` helper and `useSitemap`
hook, and redirects through loaders.

From the v1 line, also included: [route masks](/docs/hooks-useRouter),
[scroll position groups](/docs/hooks-useScrollGroup),
[route validation](/docs/routing-loader), [useBlocker](/docs/hooks-useBlocker),
and the [Protected](/docs/components-Protected) component. Environment guard
imports (`server-only`, `client-only`, `native-only`, `web-only`) with an
`environmentGuards` config option keep platform code out of the wrong bundle.

## Web, rendering, and builds

Rendering and build work since the v1 beta:

- [Render modes](/docs/render-modes) per page or globally, with layout
  render modes through `_layout+ssg.tsx` and `_layout+ssr.tsx` root layouts,
  and `.server.ts` platform extension support.
- [Skew protection](/docs/guides-skew-protection) with an optional proactive
  mode, CDN edge caching for SSG and SPA pages, and retry of transient
  dynamic-import failures before reloading.
- Startup and dev speed: `optimization.warmRoutes` with passive dependency
  tracking, `native: false` for web-only projects, an experimental bundled dev
  mode behind a flag (Vite 8.1 FullBundleDev), multicore static builds through
  a worker pool, and `ONE_PORT` and `ONE_FORCE_PORT` for tooling.
- Loading and images: [loader HMR](/docs/routing-loader) with `watchFile`,
  [`?imagedata` imports](/docs/guides-images) for dimensions and blur
  placeholders, intent-based [link prefetching](/docs/configuration), cached
  route sync dispatch, and automatic layout CSS inlining.
- Framework depth: flexible React Compiler options, `.server.ts` support,
  subdomain on loader props, API middleware fixes with a unified server build
  mode, and a daemon for multi-app development.

## Deployment, updates, and data

Cloudflare Workers support arrived with lazy module loading, adoption of the
Cloudflare Vite plugin worker build, merged user `wrangler.jsonc`, and worker
env and `executionCtx` exposed to API handlers. Vercel deploys warn when
`vercel.json` is missing `cleanUrls`. See
[deployment](/docs/guides-deployment).

Over-the-air updates are documented in the
[OTA updates guide](/docs/guides-ota-updates), covering expo-updates and
hot-updater with the generated EXUpdates manifest. Data loading keeps
[typed loaders](/docs/routing-loader) with refetching,
[middleware](/docs/routing-middlewares), and sitemaps with per-route
overrides.

## Developer experience

DevTools became a unified panel with SEO preview, route debugging, loader
timing, error tracking, and a source inspector with picker UI and input
recording. Editor detection and configuration improved, MDX gained smart
typography and automatic loader HMR, `EXPO_PUBLIC_` stays accepted next to
the default `ONE_PUBLIC_` prefix with one-way aliasing, and `--skip-env`
skips env loading. See
[DevTools](/docs/dev-tools) and [environment](/docs/environment).

The site itself added build-time open graph images for posts and an RSS feed
for this blog.

## Requirements

The v2 line requires React 19 (19.2.3 or later) and React Native 0.87, with
0.87.1 for One native. Apps using One native build for iOS 17 and
later and use the New Architecture on native, since the library ships Fabric
components. Navigation peers moved to React Navigation 8 alphas. Metro mode
remains the compatibility path for apps that need it.
