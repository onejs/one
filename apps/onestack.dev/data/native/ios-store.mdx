---
title: iOS Store Views
description: StoreKit's ProductView, StoreView, and SubscriptionStoreView under One.iOS
---

StoreKit's merchandising views under `One.iOS`. StoreKit loads each product
from the App Store, draws its name, price, and buy button, and runs the
purchase sheet when the person taps it.

- Product identifiers come from App Store Connect, or from a StoreKit
  configuration file while you develop.
- A product that does not load shows StoreKit's own unavailable state.
- These views throw on web and Android. Keep them in an iOS branch or an
  `.ios.tsx` file.

To list products, buy them, and read entitlements from code, use
[Purchases](/native/purchases).

```tsx
import { One } from 'one'

<One.iOS.ProductView id="com.example.coins.100" />
<One.iOS.SubscriptionStoreView groupID="21482456" style={{ height: 420 }} />
```

## Bound initializers

The binding uses `ProductView(id:prefersPromotionalIcon:)`,
`StoreView(ids:prefersPromotionalIcon:)`, and the `SubscriptionStoreView`
`groupID:visibleRelationships:` or `productIDs:` initializers. The SDK
specializes these overloads to its default icon and marketing views.

Overloads accepting `StoreKit.Product` objects, icon builders or marketing
content are not bound. Their arguments include native product values and
callbacks returning generic SwiftUI views, which this generated constructor
bridge cannot carry. Pass catalog identifiers to the bound overloads.

Xcode's local StoreKit configuration can exercise catalog rendering on the
simulator without an account or real payment. That test catalog does not
establish App Store catalog availability, purchases, subscription eligibility
or entitlements for a signed app and account.
