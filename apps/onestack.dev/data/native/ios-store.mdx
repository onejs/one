title: iOS Store Views

StoreKit's merchandising views under `One.iOS`: `ProductView` for one
product, `StoreView` for a list, and `SubscriptionStoreView` for a
subscription group. StoreKit loads each product from the App Store, draws its
name, price, and buy button, and runs the purchase sheet when the person taps
it.

Product identifiers come from App Store Connect, or from a StoreKit
configuration file while you develop. A product that does not load shows
StoreKit's own unavailable state. To list products, buy them, and read
entitlements from code, use [Purchases](/native/purchases). These views throw
on web and Android.

## Usage

```tsx
import { One } from 'one'

function Store() {
  return (
    <>
      <One.iOS.ProductView id="com.example.coins.100" />
      <One.iOS.SubscriptionStoreView groupID="21482456" style={{ height: 420 }} />
    </>
  )
}
```

## How it works

The binding uses `ProductView(id:prefersPromotionalIcon:)`,
`StoreView(ids:prefersPromotionalIcon:)`, and the `SubscriptionStoreView`
`groupID:visibleRelationships:` or `productIDs:` initializers. Overloads
accepting `StoreKit.Product` objects, icon builders, or marketing content are
not bound: their arguments include native product values and callbacks
returning generic SwiftUI views, which the generated constructor bridge
cannot carry. Pass catalog identifiers to the bound overloads.

## ProductView

One product with its icon, name, description, and buy button.

```tsx
import { One } from 'one'

function Coins() {
  return <One.iOS.ProductView id="com.example.coins.100" prefersPromotionalIcon />
}
```

## StoreView

A list of products, each drawn as a `ProductView`.

```tsx
import { One } from 'one'

function CoinStore() {
  return <One.iOS.StoreView ids={['com.example.coins.100', 'com.example.coins.500']} />
}
```

## SubscriptionStoreView

The subscription store for one group of auto-renewable subscriptions. Pass
exactly one of `groupID` and `productIDs`; both or neither throws.
`visibleRelationships` applies only with `groupID` and throws with
`productIDs`. Give it a height, since it fills the box React Native gives it.

```tsx
import { One } from 'one'

function Subscribe() {
  return (
    <One.iOS.SubscriptionStoreView
      groupID="21482456"
      visibleRelationships="all"
      style={{ height: 420 }}
    />
  )
}
```

## Platform differences

| | iOS | Android | Web |
| --- | --- | --- | --- |
| Renders | StoreKit views | Throws | Throws |
| Catalog | App Store | None | None |
| Purchase | System sheet | None | None |

## Limits and gotchas

- **One subscription source.** Exactly one of `groupID` and `productIDs`,
  and `visibleRelationships` only with `groupID`.
- **Develop with a config file.** Xcode's local StoreKit configuration
  exercises catalog rendering on the simulator without an account or real
  payment. That test catalog does not establish App Store availability,
  purchases, subscription eligibility, or entitlements for a signed app.
