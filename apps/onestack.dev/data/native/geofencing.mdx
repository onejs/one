---
title: Geofencing
description: Monitor circular regions for enter and exit events
---

`One.Location` monitors circular regions for arrivals and departures:
alert when the user reaches the office, silence notifications at home, or
log a store visit. Each region is an identifier, a center, and a radius
in meters, with entry and exit notifications that default on. For
one-shot positions and address lookup, see location.

On iOS regions run on `CLLocationManager` with `CLCircularRegion`,
keeping Core Location's names, inputs, and composition. On Android the
same calls drive software regions over the platform location providers,
with no Play Services dependency. On web there is no region monitoring:
submits resolve without effect, the list stays empty, state reads
unknown, listeners never fire, and the always grant reads denied.

## Usage

```tsx
import { One } from 'one'

const permission = await One.Location.requestAlwaysAuthorization()
if (permission === 'always' || permission === 'whenInUse') {
  await One.Location.startMonitoring({
    identifier: 'office',
    center: { latitude: 37.7749, longitude: -122.4194 },
    radius: 100,
  })
  const entered = One.Location.addDidEnterRegionListener((region) => {
    console.log('entered', region.identifier)
  })
  const exited = One.Location.addDidExitRegionListener((region) => {
    console.log('exited', region.identifier)
  })
}
```

The listeners stand in for the location manager delegate, each receiving
the region only. Remove them when the screen no longer needs events, and
stop each region promptly when tracking ends to spare the battery.

## How it works

Request the always grant while the app is active, usually after a tap.
It resolves with the resulting status: not determined, restricted,
denied, when in use, or always. An existing decision returns without
another prompt. On Android 11 and newer the background grant is
requested second; without `location.background` in the manifest the
status reaches when-in-use at best. The request rejects when the usage
text is missing or the app is inactive.

Add the prompt strings and background flag to the manifest:

```ts
import { one } from 'one/vite'

export default {
  plugins: [
    one({
      native: {
        app: {
          name: 'MyApp',
          location: {
            whenInUse: 'Show places near you.',
            alwaysAndWhenInUse: 'Alert when you arrive or leave saved places.',
            background: true,
          },
        },
      },
    }),
  ],
}
```

`whenInUse` stamps the in-use description and foreground Android
permissions; `alwaysAndWhenInUse` stamps the always description, which
the always request requires on iOS. `background: true` adds `location`
to the background modes and stamps the background location permission;
background watches and region monitoring then run under a
location-type foreground service with a persistent notification while
registered.

Each `startMonitoring` call adds one region: up to 20 on iOS, 100 on
Android, beyond which it rejects. Starting an unchanged region resolves
without restarting it; stopping an unmonitored identifier resolves
without effect. Invalid regions throw a `TypeError` at the JavaScript
boundary before reaching native. Starting without permission rejects,
and unavailable hardware rejects too: the iOS simulator has no
region-monitoring hardware, so delivery needs a device. Monitored
regions report a state of unknown, inside, or outside. No event fires
for the initial determination; call `requestState`, which rejects for
unmonitored identifiers. Regions with entry or exit notifications off
never emit that event, but their state still tracks.

On iOS the system can wake a terminated app on a new region event. On
Android a terminated app does not restart for region events, so start
monitoring again after a fresh launch.

## Platform differences

| | iOS | Android | Web |
| --- | --- | --- | --- |
| Engine | Location hub | Software fences | None |
| Limit | 20 regions | 100 regions | Empty |
| Terminated | Wakes app | Stays dead | Never |
| Service | Background mode | Foreground note | None |

## Limits and gotchas

- **Monitoring costs battery.** Regions keep location hardware active.
  Stop every region the moment tracking ends.
- **No event for the first fix.** Listeners fire on crossings only.
  Call `requestState` for the current inside or outside.
- **Unchanged restarts are free.** Starting the same region resolves
  without restarting it, so re-submits after launch stay cheap.
- **Android needs a fresh start.** A terminated app never restarts for
  region events there; re-monitor on every launch.
- **The simulator has no fences.** iOS region calls reject there.
  Prove enter and exit delivery on a device.
- **Flags gate events, not state.** A region with entry off still
  tracks inside and outside; it just never emits that crossing.

## Examples

### Alert on arriving at the office

```tsx
import { useEffect } from 'react'
import { One } from 'one'

const OFFICE = {
  identifier: 'office',
  center: { latitude: 37.7749, longitude: -122.4194 },
  radius: 100,
}

function useOfficeArrival(onArrive: (at: number) => void) {
  useEffect(() => {
    async function monitor() {
      const permission = await One.Location.requestAlwaysAuthorization()
      if (permission !== 'always' && permission !== 'whenInUse') return
      await One.Location.startMonitoring(OFFICE)
      const state = await One.Location.requestState(OFFICE.identifier)
      if (state === 'inside') onArrive(Date.now())
      return One.Location.addDidEnterRegionListener(() => onArrive(Date.now()))
    }
    const subscription = monitor()
    return () => {
      void subscription.then((sub) => sub?.remove())
      void One.Location.stopMonitoring(OFFICE.identifier)
    }
  }, [onArrive])
}
```

The initial state check catches a user who opens the app already inside,
since no enter event fires for them. Cleanup removes the listener and
the region together.

### Silence notifications at home

```tsx
import { useEffect, useState } from 'react'
import { One } from 'one'

const HOME = {
  identifier: 'home',
  center: { latitude: 37.3382, longitude: -121.8863 },
  radius: 150,
  notifyOnEntry: true,
  notifyOnExit: true,
}

function useAtHome() {
  const [atHome, setAtHome] = useState(false)

  useEffect(() => {
    async function monitor() {
      const permission = await One.Location.requestAlwaysAuthorization()
      if (permission !== 'always' && permission !== 'whenInUse') return
      await One.Location.startMonitoring(HOME)
      setAtHome((await One.Location.requestState(HOME.identifier)) === 'inside')
      const entered = One.Location.addDidEnterRegionListener(() => setAtHome(true))
      const exited = One.Location.addDidExitRegionListener(() => setAtHome(false))
      return () => {
        entered.remove()
        exited.remove()
      }
    }
    const cleanup = monitor()
    return () => {
      void cleanup.then((remove) => remove?.())
      void One.Location.stopMonitoring(HOME.identifier)
    }
  }, [])

  return atHome
}
```

Both crossings drive one boolean, seeded by the current state so the
first render is already right. Screens read the boolean and mute
themselves without touching regions at all.
