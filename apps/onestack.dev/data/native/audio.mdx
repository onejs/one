title: Audio
description: Play tracks, record microphone files, and answer lock screen controls

`One.Audio` plays local files and remote URLs, records the microphone to
AAC files, and answers interruptions and lock screen controls. It offers
two playback shapes: a singleton (`play`, `pause`, `resume`, `seek`,
`stop`) that holds one track at a time, and independent `AudioPlayer`
instances from `createPlayer` or `useAudioPlayer`, each with its own
position, volume, and rate.

On iOS playback runs on `AVPlayer` and recording on `AVAudioRecorder`,
with `MPNowPlayingSession` and the remote command center behind lock
screen controls. On Android playback runs on `MediaPlayer` and recording
on `MediaRecorder`, with audio focus driving interruptions and a
`MediaSession` behind the controls. On web an `HTMLAudioElement` plays
and `MediaRecorder` plus `getUserMedia` records.

## Usage

```tsx
import { One } from 'one'

await One.Audio.play('https://example.com/episode.m4a')
const status = await One.Audio.getPlaybackStatus()
if (status.state === 'playing') {
  await One.Audio.pause()
  await One.Audio.seek(30_000)
  await One.Audio.resume()
}
await One.Audio.stop()
```

The singleton plays one URI at a time and reports its state on every call,
so a screen can drive transport buttons straight from the returned status.

## How it works

The singleton `play()` builds a player for the URI, replacing any previous
one, and switches the shared audio session to the playback category on
iOS. Every transport call resolves with the playback status: the state
(idle, loading, playing, paused, ended, or failed), the URI, the position,
the duration when finite, and the error when failed. A remote source can
report loading until enough data arrives; `seek` needs a ready item and
rejects while loading or failed. `resume` restarts an ended item from the
beginning. Starting playback replaces the previous player; stop a paused
player before recording. All native work runs through the main thread on
both platforms, and every failure rejects with an `Error` whose `code`
holds the stable `E_AUDIO_*` value.

Recording writes AAC in an `.m4a` file under the app cache on native.
Request the recording permission first; playback alone needs none. Set
`native.app.audio.microphone` to the purpose string before prebuild: it
becomes `NSMicrophoneUsageDescription` on iOS and stamps `RECORD_AUDIO`
into the Android manifest. Recording and playback cannot run together.
The recorder pauses on interruption and reports paused, so resume after
the interruption ends. Files in cache can be evicted, so move a keeper to
permanent storage with `One.FileSystem.move`.

`watchInterruptions` reports when another session takes over: the type is
began or ended, and `shouldResume` is the system's recommendation, not an
automatic action. One pauses its own player or recorder on began; resume
only after ended, per your own policy. On iOS the notice comes from
`AVAudioSession` on the main queue; on Android it comes from audio focus
loss. `watchRemoteCommands` reports play, pause, and seek from the system
controls, with the position on seek, after your screen registers metadata
with `setNowPlayingInfo`. Artwork must be an existing local `file://`
image, so download remote art to cache first. `stop` or a new `play`
clears the metadata and handlers; `clearNowPlayingInfo` removes them while
the player keeps playing.

For playback with another app in front, set
`native.app.audio.background: true` and rerun prebuild. On iOS this adds
`audio` to the background modes and playback activates the playback
category before the app backgrounds. On Android it stamps a
`mediaPlayback` foreground service that runs while audio plays.

Player instances are independent of each other and of the singleton. The
source is a URI string, `{ uri, headers, name }`, or `null` for a player
with no media yet; numeric asset ids throw, so bundle audio as a file and
pass its URI. Options are `{ updateInterval, crossOrigin }`: the status
poll interval in milliseconds (default 500, driving `addListener` and
`useAudioPlayerStatus`) and the web-only CORS mode. `useAudioPlayer`
creates one player, replaces its source when the source value changes,
and removes it on unmount. `useAudioPlayerStatus` returns the current
status and re-renders on every update. Time reads in seconds.
`setPlaybackRate` changes speed without reloading: 0 to 2 on iOS and web,
0.1 to 2 on Android, else `E_AUDIO_RATE`. Pitch quality is iOS only.
Source headers apply on iOS and Android and are ignored on web.

On web, URI inputs use browser HTTP, HTTPS, data, or blob URLs, and
autoplay policy can reject playback without a user gesture. A stopped
recording returns its encoded byte length and a blob URL in the browser's
own codec; release it with `URL.revokeObjectURL` when finished. The Media
Session API supplies metadata and remote commands when present. OS audio
interruptions have no browser equivalent, so `watchInterruptions` keeps
an inert remover there.

## Platform differences

| | iOS | Android | Web |
| --- | --- | --- | --- |
| Engine | AVPlayer | MediaPlayer | Audio element |
| Recorder | AAC file in cache | AAC file in cache | Blob URL |
| Interrupt | Session notice | Audio focus | None, inert |
| Controls | Lock screen session | Media session | Media Session |
| Background | Audio mode | Foreground service | Tab must stay open |
| Mic setup | Usage text | Runtime permission | Browser prompt |

## Limits and gotchas

- **The singleton plays one thing at a time.** A new `play` replaces the
  current track. Use player instances for overlapping or independent tracks.
- **Playback owns the shared session.** It switches the category, which can
  replace another feature's audio setup. Stop audio before speech
  recognition or another audio feature.
- **Recordings live in cache; move what you keep.** Stop returns a cache
  file the system can evict. Move keepers with `One.FileSystem.move`.
- **A removed player stays removed.** Every method after `remove` throws.
  The hooks remove on unmount; hand-created players need one `remove` call.
- **Web playback needs a gesture.** Autoplay policy can reject `play`
  called outside a user action.
- **Resume restarts an ended singleton.** There is no stay-at-end state;
  seeking back first gives the same result explicitly.

## Examples

### Play an episode with a speed toggle

```tsx
import { Button, Text } from 'react-native'
import { useAudioPlayer, useAudioPlayerStatus } from 'one'

function Episode({ uri }: { uri: string }) {
  const player = useAudioPlayer(uri)
  const status = useAudioPlayerStatus(player)

  function toggleSpeed() {
    player.setPlaybackRate(status.playbackRate === 1 ? 1.5 : 1)
  }

  return (
    <>
      <Button
        title={status.playing ? 'Pause' : 'Play'}
        onPress={() => (status.playing ? player.pause() : player.play())}
      />
      <Button title={`${status.playbackRate}x speed`} onPress={toggleSpeed} />
      <Text>
        {Math.floor(status.currentTime)}s of {Math.floor(status.duration)}s
      </Text>
    </>
  )
}
```

The hook owns the player lifetime: it creates the player, reloads it when
the URI changes, and removes it on unmount. The status hook re-renders the
screen on every poll tick, so transport UI stays current.

### Record a memo and keep it

```tsx
import { useState } from 'react'
import { Button, Text } from 'react-native'
import { One } from 'one'

function MemoRecorder({ keepDir }: { keepDir: string }) {
  const [kept, setKept] = useState('')

  async function record() {
    const permission = await One.Audio.requestRecordingPermission()
    if (permission !== 'granted') return
    await One.Audio.startRecording()
  }

  async function finish() {
    const recorded = await One.Audio.stopRecording()
    const keptUri = `${keepDir}/memo.m4a`
    await One.FileSystem.move(recorded.uri, keptUri)
    setKept(keptUri)
  }

  return (
    <>
      <Button title="Record" onPress={record} />
      <Button title="Stop and keep" onPress={finish} />
      {kept ? <Text>Kept {kept}</Text> : null}
    </>
  )
}
```

Recording starts only after the grant, and stopping returns the cache file
at once. Moving it out of cache before anything else makes the memo
survive eviction.

### Drive lock screen controls

```tsx
import { useEffect } from 'react'
import { One } from 'one'

function useNowPlaying(trackUri: string, title: string, artist: string) {
  useEffect(() => {
    async function setup() {
      await One.Audio.play(trackUri)
      await One.Audio.setNowPlayingInfo({ title, artist })
    }
    setup()
    const stopWatching = One.Audio.watchRemoteCommands((event) => {
      void One.Audio.getPlaybackStatus().then((status) => {
        console.log(event.type, status.state, status.positionMs)
      })
    })
    return () => {
      stopWatching()
      void One.Audio.stop()
    }
  }, [trackUri, title, artist])
}
```

Metadata goes up after playback starts, since the controls attach to the
current player. The remote listener only observes; the handlers already
drove the player, so the screen just syncs its own state.
