title: Platform Support

---

Every One native API is importable on all three platforms, so one component
tree builds everywhere. What differs is what a call does when it runs. This
page sums that up per API; each name links to its page, whose Platform
differences section has the details.

## Reading the table

- **Yes** means the API works with the platform's own implementation.
- **Throws** means rendering the view or calling the API throws an error.
  Keep it behind a platform check.
- **Rejects** means the call returns a promise that rejects, so a `catch`
  covers it.
- **Nothing**, **No effect**, and **Empty** mean the call is safe and does
  nothing, or reads an empty value.
- Other words name the mechanism or the limit on that platform.

During server rendering there is no device or browser, so services read as
unavailable there.
