---
title: Speech
description: Stream dictation through the platform speech recognizer
---

`One.Speech` provides speech recognition (dictation) through the native platform recognizer on iOS and Android, and the Web Speech API on web browsers.

```tsx
import { One } from 'one'

if (!One.Speech.isAvailable()) {
  console.log('Speech recognition not available')
  return
}

const permissions = await One.Speech.requestPermissions()
if (!permissions.granted) return

const session = One.Speech.start({ lang: 'en-US' }, (event) => {
  if (event.type === 'transcript') {
    console.log('Heard:', event.transcript)
  } else if (event.type === 'error') {
    console.error('Error:', event.error, event.message)
  } else if (event.type === 'end') {
    console.log('Final:', event.transcript)
  }
})

setTimeout(() => session.stop(), 5000)
```

`isAvailable()` reports whether the platform recognizer is available. `getPermissions()` and `requestPermissions()` return a permission response with `status` ('granted', 'denied', or 'undetermined'), a boolean `granted` flag, and `canAskAgain`. On iOS, `restricted` indicates screen time or device management blocks the feature.

`start(options, onEvent)` begins listening and returns a session handle. Pass optional `lang` (a BCP-47 tag such as `en-US`); it defaults to the device language. `onEvent` receives events with a `type` ('start', 'transcript', 'end', or 'error'), the full `transcript` so far, and on error, an `error` code and optional `message`.

The session returns `stop()` and `abort()`. `stop()` finishes listening and emits a final `end` event with the complete transcript. `abort()` ends silently with no further events. Starting a new session replaces the previous one; its callback and handle no longer affect the recognizer.

On iOS and Android, configure `native.app.speech` with usage descriptions:

```json
{
  "native": {
    "app": {
      "speech": {
        "recognition": "We need microphone access for dictation",
        "microphone": "We need microphone access for dictation"
      }
    }
  }
}
```

Without the configuration, speech recognition throws `MissingPermissionError`. On web, the SpeechRecognition or webkitSpeechRecognition API provides dictation where supported. `isAvailable()` reflects constructor availability, but the browser's recognition service can still reject a session. Permission methods check or request microphone access; a denied recognition service also marks permission denied. Browsers may prompt again when recognition starts and may require a user gesture. Without a recognizer, `isAvailable()` returns false, permissions report denied, and `start` throws.
