`One.Speech` streams dictation from the microphone: live transcript
updates while the user talks, then one closing event. Reach for it for
voice notes, search-by-voice, and hands-free form entry. For reading text
aloud, see speech synthesis.

On iOS an `SFSpeechRecognizer` fed from `AVAudioEngine` transcribes. On
Android the system `SpeechRecognizer` transcribes. On web the browser's
speech recognition supplies dictation where present.

## Usage

```tsx
import { One } from 'one'

export async function dictate(onText: (text: string) => void) {
  if (!One.Speech.isAvailable()) return null

  const permissions = await One.Speech.requestPermissions()
  if (!permissions.granted) return null

  return One.Speech.start({ lang: 'en-US' }, (event) => {
    if (event.type === 'transcript' || event.type === 'end') onText(event.transcript)
    if (event.type === 'error') console.error(event.error, event.message)
  })
}
```

`start` returns a session with `stop` and `abort`. Every event carries
the whole transcript so far, so the screen always renders the latest
event's text.

## How it works

One session runs at a time. Starting another replaces the running one,
whose callback never fires again and whose session handle goes inert.
The session emits `start`, full `transcript` updates, then exactly one
`end` or `error`. `stop` finishes listening and the final transcript
arrives in `end`, including after trailing silence or no speech at all.
`abort` tears the session down with no further events. Errors carry one
of eight codes, from not-allowed and audio-capture to network and busy,
plus an optional message.

Permissions resolve granted, denied, or undetermined, with granted and
can-ask-again flags. On iOS `restricted` adds that Screen Time or device
management blocks recognition. Set `native.app.speech` so prebuild
writes both iOS usage descriptions and the Android recognition-service
query:

```ts
import { one } from 'one/vite'

export default {
  plugins: [
    one({
      native: {
        app: {
          name: 'MyApp',
          speech: {
            recognition: 'Dictate notes by voice',
            microphone: 'Dictate notes by voice',
          },
        },
      },
    }),
  ],
}
```

On web, availability reflects constructor presence, but the browser's
recognition service can still reject a session for network or service
reasons. Permission methods check or request microphone access, and a
denied recognition service also reads denied. Browsers may prompt again
when recognition starts and may need a user gesture. Without a
recognizer, permissions read denied and `start` throws; server rendering
keeps the same unavailable contract.

## Platform differences

| | iOS | Android | Web |
| --- | --- | --- | --- |
| Engine | System recognizer | System recognizer | Browser API |
| Audio | Engine tap | System capture | Browser capture |
| Transcript | Whole so far | Whole so far | Whole so far |
| Restriction | Flagged | Denied | Denied |

## Limits and gotchas

- **One session at a time.** A new `start` kills the old session
  silently. Hold one session per screen and stop it on unmount.
- **Render the latest transcript.** Every event carries the whole text
  so far; never append events together.
- **End always closes.** A session finishes with exactly one `end` or
  `error`, even on silence. `abort` is the only silent exit.
- **Recognition needs the network.** On-device exceptions aside, most
  sessions transcribe server-side; airplane mode surfaces as a network
  error.
- **Stop audio features first.** Recognition owns the microphone like
  the recorder does; concurrent audio sessions conflict.

## Examples

### Dictate into a note field

```tsx
import { useRef, useState } from 'react'
import { Button, Text } from 'react-native'
import { One } from 'one'

function VoiceNote() {
  const [text, setText] = useState('')
  const [live, setLive] = useState(false)
  const session = useRef<ReturnType<typeof One.Speech.start> | null>(null)

  async function toggle() {
    if (session.current) {
      session.current.stop()
      return
    }
    const permissions = await One.Speech.requestPermissions()
    if (!permissions.granted || !One.Speech.isAvailable()) return
    setLive(true)
    session.current = One.Speech.start({ lang: 'en-US' }, (event) => {
      if (event.type === 'end' || event.type === 'error') {
        session.current = null
        setLive(false)
      }
      setText(event.transcript)
    })
  }

  return (
    <>
      <Button title={live ? 'Stop' : 'Dictate'} onPress={toggle} />
      <Text>{text}</Text>
    </>
  )
}
```

The ref holds the session across renders while state tracks the live
flag and transcript. The closing event clears both, so a second tap
starts fresh.

### Search by voice with error feedback

```tsx
import { useState } from 'react'
import { Button, Text } from 'react-native'
import { One } from 'one'

function VoiceSearch({ search }: { search: (query: string) => void }) {
  const [message, setMessage] = useState('')

  async function listen() {
    if (!One.Speech.isAvailable()) {
      setMessage('Voice search is unavailable here.')
      return
    }
    const permissions = await One.Speech.requestPermissions()
    if (!permissions.granted) {
      setMessage('Microphone access is needed for voice search.')
      return
    }
    One.Speech.start({}, (event) => {
      if (event.type === 'end' && event.transcript.trim()) {
        search(event.transcript.trim())
      } else if (event.type === 'error') {
        setMessage('Sorry, I did not catch that. Try again.')
      }
    })
  }

  return (
    <>
      <Button title="Search by voice" onPress={listen} />
      {message ? <Text>{message}</Text> : null}
    </>
  )
}
```

The default device language fits search, so options stay empty. Only a
nonblank closing transcript searches; errors show a retry hint instead
of searching on a fragment.
