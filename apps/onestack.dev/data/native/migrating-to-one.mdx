---
title: Migrating to One Native
description: Moving an app from Expo and community native packages onto One's native modules
---

Most of One's native modules keep the API shape of the package they
replace, so migrating is usually an import change plus the renames below.
Options that a table does not list have no One equivalent.

```tsx
// before
import * as Clipboard from 'expo-clipboard'
await Clipboard.setStringAsync(text)

// after
import { One } from 'one'
await One.Clipboard.setString(text)
```

## Clipboard

From `expo-clipboard`. See [Clipboard](/native/clipboard).

| expo-clipboard | One |
|---|---|
| `getStringAsync()` | `One.Clipboard.getString()` |
| `setStringAsync(text)` | `One.Clipboard.setString(text)` |
| `hasStringAsync()` | `One.Clipboard.hasString()` |

## Network

From `expo-network`. Import `useNetworkState` directly from `one`. See [Network](/native/network).

| expo-network | One |
|---|---|
| `getNetworkStateAsync()` | `One.Network.getState()` |
| `addNetworkStateListener(fn)` | `One.Network.addStateListener(fn)` |
| `useNetworkState()` | `useNetworkState()` |
| `NetworkStateType.WIFI` | `'wifi'` (and likewise for every member) |

## Browser

From `expo-web-browser`. See [Browser](/native/browser).

| expo-web-browser | One |
|---|---|
| `openBrowserAsync(url, options?)` | `One.Browser.open(url, options?)` |
| `dismissBrowser()` | `One.Browser.dismiss()` |
| `openAuthSessionAsync(url, redirectUrl?, options?)` | `One.Browser.openAuthSession(url, redirectUrl?, options?)` |
| `dismissAuthSession()` | `One.Browser.dismissAuthSession()` |
| `WebBrowserResult` | `BrowserResult` |
| `WebBrowserResultType` | `BrowserResultType` |
| `WebBrowserPresentationStyle` | `BrowserPresentationStyle` |
| `ERR_WEB_BROWSER_BLOCKED` | `E_BROWSER_BLOCKED` |

## Secure store

From `expo-secure-store`. See [SecureStore](/native/secure-store).

| expo-secure-store | One |
|---|---|
| `getItemAsync(key)` | `One.SecureStore.getItem(key)` |
| `setItemAsync(key, value)` | `One.SecureStore.setItem(key, value)` |
| `deleteItemAsync(key)` | `One.SecureStore.deleteItem(key)` |
| `getItem(key)` | `One.SecureStore.getItemSync(key)` |
| `setItem(key, value)` | `One.SecureStore.setItemSync(key, value)` |

## Storage

Use [One.Storage](/native/storage) for string settings and caches on iOS,
Android, and web. It replaces the iOS-only Preferences service from earlier
v2 betas; Preferences was not part of v1.
The verbs are synchronous:

| Previous One API | Current API |
| --- | --- |
| `One.iOS.Preferences.getItem(key)` or `getItemSync(key)` | `One.Storage.getItem(key)` |
| `One.iOS.Preferences.setItem(key, value)` or `setItemSync(key, value)` | `One.Storage.setItem(key, value)` |
| `One.iOS.Preferences.deleteItem(key)` or `deleteItemSync(key)` | `One.Storage.removeItem(key)` |

Storage uses its own log. Existing Preferences values are not migrated
automatically. They remain in `UserDefaults.standard` under keys prefixed
with `One.Preferences.`, such as `One.Preferences.theme` for the key `theme`.
To retain them, add app-owned native migration code that reads those string
values and passes them to JavaScript, then write them with
`One.Storage.setItem` using the original keys without the prefix. Complete
the copy before deleting the old defaults.

The new beta has no Preferences JavaScript API, and the older betas with
Preferences have no Storage API, so this requires a native bridge in your
app; it cannot be done by calling both services in JavaScript. Without that
migration, Storage starts without your previous settings. Keep secrets in
SecureStore.

## Portals and pages

Replace `react-native-teleport` with [One.UI.Portal and PortalHost](/native/portal),
remove `PortalProvider`, and mount a named host for each overlay destination.
Replace `react-native-pager-view` with [One.UI.Pager](/native/ui-pager) and import
`PagerRef` from `one` for its ref. Give the pager finite bounds and each direct
page view a stable key. It is separate from the SwiftUI `One.iOS.Pager`.

## Image picker

From `expo-image-picker`. See [ImagePicker](/native/image-picker).

| expo-image-picker | One |
|---|---|
| `launchImageLibraryAsync` | `One.ImagePicker.launchLibrary` |
| `launchCameraAsync` | `One.ImagePicker.launchCamera` |
| `getCameraPermissionsAsync` | `One.ImagePicker.getCameraPermissions` |
| `requestCameraPermissionsAsync` | `One.ImagePicker.requestCameraPermissions` |

`mediaTypes` and `selectionLimit` are the whole options surface;
`allowsEditing`, `quality`, `aspect`, and the rest have no equivalent.

## Document picker

From `expo-document-picker`. See [DocumentPicker](/native/document-picker).

| expo-document-picker | One |
|---|---|
| `getDocumentAsync` | `One.DocumentPicker.getDocument` |

`copyToCacheDirectory` has no equivalent because files are always copied.
Reads through `expo-file-system` become `fetch(uri)`.

## Notifications

From `expo-notifications`. See [Notifications](/native/notifications).
Payload, permission, and push token shapes are the same. Platform enums
become string unions, and channel importance still accepts the numbers 0 to 5.

## Maps

From `react-native-maps`. See [Map](/native/map).

Convert the region to a camera: `zoom = log2(360 * widthPt / 256 / longitudeDelta)`,
where `widthPt` is the map view width in points, and center coordinates as-is.
Marker children become the `markers` array, and `onRegionChangeComplete`
becomes `onCameraMove`. Designs that need custom pin views, callouts, or
camera refs have no equivalent yet; keep `react-native-maps` for those screens.

## Splash screen

From `expo-splash-screen`. `one prebuild` keeps the launch screen (the iOS
storyboard, the Android splash) up until React Native draws its first content.
Expo-prebuilt apps get the same hold by dropping `expo-splash-screen` and
passing `holdLaunchScreen: true` to `vxrn/expo-plugin`. To keep it up beyond
the first content, call `One.LaunchScreen.preventAutoHide()` while modules
evaluate, then `One.LaunchScreen.hide()` when the app is ready. See
[Launch screen](/native/launch-screen).

## Build tooling

Expo apps keep Expo prebuild with the `vxrn/expo-plugin` adapter. Apps
without Expo use `one prebuild` from `native.app`. See
[Build or Run iOS](/docs/guides-ios-native) and [Ship with EAS](/docs/guides-eas).
