`One.UI.Pager` shows one child view per page and swipes between them.
iOS uses a paging `UIScrollView`, Android uses `ViewPager2`, and web uses
CSS scroll snap.

- Every page stays in the React tree, so state and context survive a swipe.
- `onPageScroll` reports continuous progress during drags and settles.
- The ref moves pages with or without animation.
- It replaces `react-native-pager-view` without other changes.

## Usage

Give the pager a size and give each page a stable `key`. Each direct child
fills the pager.

```tsx
import { useRef, useState } from 'react'
import { One, type PagerRef } from 'one'
import { Button, Text, View } from 'react-native'

export function Onboarding() {
  const pager = useRef<PagerRef>(null)
  const [page, setPage] = useState(0)

  return (
    <View style={{ flex: 1 }}>
      <One.UI.Pager
        ref={pager}
        style={{ flex: 1 }}
        onPageSelected={({ nativeEvent }) => setPage(nativeEvent.position)}
      >
        <View key="welcome">
          <Text>Welcome</Text>
        </View>
        <View key="sync">
          <Text>Sync</Text>
        </View>
        <View key="done">
          <Text>Done</Text>
        </View>
      </One.UI.Pager>
      <Button
        title={page === 2 ? 'Start' : 'Next'}
        onPress={() => pager.current?.setPage(Math.min(page + 1, 2))}
      />
    </View>
  )
}
```

### Page indicators

`onPageScroll` sends `position + offset` as a continuous value. To drive
animation from it on the UI thread, wrap the pager with Reanimated's
`createAnimatedComponent` and pass a worklet handler from `useEvent`. The
indicator then follows the swipe even while the JS thread is busy, and the
ref keeps its methods.

```tsx
import { One } from 'one'
import Animated, {
  useAnimatedStyle,
  useEvent,
  useSharedValue,
} from 'react-native-reanimated'

const AnimatedPager = Animated.createAnimatedComponent(One.UI.Pager)

export function Pages({ pages }: { pages: React.ReactNode[] }) {
  const progress = useSharedValue(0)
  const onPageScroll = useEvent<{ position: number; offset: number }>(
    (event) => {
      'worklet'
      progress.value = event.position + event.offset
    },
    ['onPageScroll']
  )
  const dot = useAnimatedStyle(() => ({
    transform: [{ translateX: progress.value * 16 }],
  }))

  return (
    <>
      <AnimatedPager style={{ height: 360 }} onPageScroll={onPageScroll}>
        {pages}
      </AnimatedPager>
      <Animated.View
        style={[{ width: 8, height: 8, borderRadius: 4, backgroundColor: 'black' }, dot]}
      />
    </>
  )
}
```

A worklet handler receives the payload directly, without `nativeEvent`. A
plain function passed as `onPageScroll` runs on the JS thread.

An index must be a nonnegative integer; anything else throws. An index past
the last page does nothing. A call made before the pager lays out moves it to
that page on first layout.

## Behavior

- Removing the selected page when it is last selects the new last page.
- A resize keeps the selected page.
- Invalid prop values throw during render on every platform.
- The pager adds no safe area or keyboard insets. Pages own them.
- Nested pagers on Android hand a swipe to the inner pager until it reaches
  its edge.

| | iOS | Android | Web |
| --- | --- | --- | --- |
| Native view | `UIScrollView` with paging | `ViewPager2` | CSS scroll snap |
| Pages mounted | All | All; `offscreenPageLimit` sets how many are attached | All |
| `overdrag` | Bounce at the ends | Ignored | Ignored |
| `offscreenPageLimit` | Ignored | Applied | Ignored |
| `overScrollMode` | Ignored | Edge glow | Ignored |

For SwiftUI pages with string selection and `One.iOS.Page` children, use
[`One.iOS.Pager`](/native/ios-tabs-pager).

## Migrating from react-native-pager-view

Replace the default import and JSX with `One.UI.Pager`, and type the ref as
`PagerRef` from `one`. The props, events, and ref methods keep their names
and payloads.
