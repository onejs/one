`One.UI.Pager` shows one child view per page and swipes between them, for
onboarding flows, image galleries, and tabbed content you swipe through. It is
a paging `UIScrollView` on iOS, Jetpack `ViewPager2` on Android, and a CSS
scroll snap container on web.

Every page stays mounted in the React tree, so state and context survive a
swipe. The props, events, and ref match `react-native-pager-view`. For
SwiftUI pages inside a SwiftUI layout, use
[One.iOS.Pager](/native/ios-tabs-pager) instead.

## Usage

```tsx
import { Text, View } from 'react-native'
import { One } from 'one'

function Welcome() {
  return (
    <One.UI.Pager style={{ flex: 1 }}>
      <View key="hello"><Text>Hello</Text></View>
      <View key="sync"><Text>Sync your notes</Text></View>
      <View key="done"><Text>All set</Text></View>
    </One.UI.Pager>
  )
}
```

Each direct child is one page and fills the pager. Give the pager a size and
each page a stable `key`.

## How it works

The pager clones each child with an absolute, full-size style and hands the
pages to a native container. Its props are checked in JavaScript first, so a
bad value throws during render on every platform.

- **iOS** places the pages side by side in a `UIScrollView` with paging on.
  The scroll view is one page plus `pageMargin` wide, so each page snaps into
  view and the margin shows only mid swipe. Progress is the scroll offset
  divided by that stride, sent on every scroll frame.
- **Android** gives the pages to `ViewPager2` through a RecyclerView adapter
  that never recycles them, so each page keeps its native views. Margins are a
  page transformer. When pagers nest, the inner one keeps the swipe until it
  can scroll no further in that direction, then hands it to the outer one.
- **Web** lays the pages out in a scroll container with mandatory scroll snap
  and reads progress from the scroll position.

The ref's methods are Fabric commands that run on the native view without a
render.

that page on first layout.

## Platform differences

| | iOS | Android | Web |
| --- | --- | --- | --- |
| Native view | Paging scroll view | ViewPager2 | Scroll snap |
| Pages attached | All | Offscreen page limit | All |
| At the first and last page | Bounces with overdrag | Glow, per overScrollMode | Scroll stays in the pager |

## Limits and gotchas

- **Each page is one view.** A string or number child throws, and a fragment
  is one page that cannot take the page style. Wrap each page in a `View`.
- **`initialPage` is read once.** Later changes are ignored; move with the
  ref instead.
- **Indexes are checked.** A ref call with a negative or fractional index
  throws. An index past the last page does nothing. A call made before the
  first layout lands on that page once the pager lays out.
- **Removing the selected last page selects the new last page.** A resize
  keeps the current page.
- **No insets are added.** The pager ignores safe area and keyboard; each
  page handles its own.
- **Drive indicators from one place.** `onPageScroll` already reports settles
  as well as drags. Use it as the only writer of progress rather than also
  setting progress from `onPageSelected`.

## Examples

### Move with buttons

```tsx
import { useRef, useState } from 'react'
import { Button, Text, View } from 'react-native'
import { One, type PagerRef } from 'one'

function Onboarding({ onDone }: { onDone: () => void }) {
  const pager = useRef<PagerRef>(null)
  const [page, setPage] = useState(0)
  const last = 2

  return (
    <View style={{ flex: 1 }}>
      <One.UI.Pager
        ref={pager}
        style={{ flex: 1 }}
        onPageSelected={({ nativeEvent }) => setPage(nativeEvent.position)}
      >
        <View key="welcome"><Text>Welcome</Text></View>
        <View key="sync"><Text>Sync</Text></View>
        <View key="done"><Text>Done</Text></View>
      </One.UI.Pager>
      <Button
        title={page === last ? 'Start' : 'Next'}
        onPress={() => (page === last ? onDone() : pager.current?.setPage(page + 1))}
      />
    </View>
  )
}
```

`onPageSelected` fires once on mount and after every swipe or `setPage`, so
`page` is right whether the user swipes or taps.

### Animate page dots

```tsx
import { View } from 'react-native'
import Animated, { useAnimatedStyle, useSharedValue, type SharedValue } from 'react-native-reanimated'
import { One } from 'one'

function Dot({ index, progress }: { index: number; progress: SharedValue<number> }) {
  const style = useAnimatedStyle(() => ({
    opacity: Math.max(0.3, 1 - Math.abs(progress.get() - index)),
  }))
  return <Animated.View style={[{ width: 8, height: 8, borderRadius: 4, backgroundColor: 'black' }, style]} />
}

function Gallery({ photos }: { photos: string[] }) {
  const progress = useSharedValue(0)
  return (
    <View>
      <One.UI.Pager
        style={{ height: 360 }}
        onPageScroll={({ nativeEvent }) => progress.set(nativeEvent.position + nativeEvent.offset)}
      >
        {photos.map((uri) => (
          <View key={uri}><One.UI.Image source={{ uri }} style={{ flex: 1 }} /></View>
        ))}
      </One.UI.Pager>
      <View style={{ flexDirection: 'row', gap: 6, justifyContent: 'center' }}>
        {photos.map((uri, index) => <Dot key={uri} index={index} progress={progress} />)}
      </View>
    </View>
  )
}
```

`position + offset` is a continuous page number, such as 1.4 between the
second and third pages. Writing it to a shared value updates the dots on the
UI thread without a React render per frame.

## Migrating from react-native-pager-view

Replace the default import and JSX with `One.UI.Pager`, and type the ref as
`PagerRef` from `one`. Props, events, and ref methods keep their names and
payloads.
