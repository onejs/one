---
title: Camera preview
description: A live camera view that takes pictures and scans QR codes and barcodes on iOS and Android
---

`CameraView` shows a live camera preview inside your layout, takes pictures
from it, and reports the QR codes and barcodes it sees. On iOS it is an
`AVCaptureSession` with photo and metadata outputs; on Android it is CameraX
with ML Kit barcode scanning. The same component is reachable as
`One.iOS.CameraView` and `One.Android.CameraView`, and picks the platform's
camera itself.

Use it when the camera belongs inside your screen: a custom shutter, an
overlay, scanning tickets or product codes. To let people take a photo in
the system camera instead, use [Image Picker](/native/image-picker).

## Usage

Declare why you use the camera in your app config before prebuild. This
writes the iOS usage text and adds Android's `CAMERA` permission:

```ts
import { one } from 'one/vite'

export default {
  plugins: [
    one({
      native: {
        app: {
          name: 'MyApp',
          imagePicker: { camera: 'Scan tickets at the door.' },
        },
      },
    }),
  ],
}
```

Then ask for permission and turn the view on:

```tsx
import { useState } from 'react'
import { Button, Text, View } from 'react-native'
import { One } from 'one'

function TicketScanner({ onTicket }: { onTicket: (code: string) => void }) {
  const [active, setActive] = useState(false)
  return (
    <View style={{ flex: 1 }}>
      <One.iOS.CameraView
        style={{ flex: 1 }}
        active={active}
        codeTypes={['qr']}
        onCodeScanned={({ data }) => {
          setActive(false)
          onTicket(data)
        }}
      />
      <Button
        title="Scan"
        onPress={async () => {
          const permission = await One.ImagePicker.requestCameraPermissions()
          if (permission.granted) setActive(true)
        }}
      />
    </View>
  )
}
```

The view never asks for permission itself, so the button asks first and
turns scanning on only after a yes.

To take a picture, hold a ref and call `takePicture` once the view reports
`ready`:

```tsx
import { useRef, useState } from 'react'
import { Button, Image, View } from 'react-native'
import { One, type CameraViewRef } from 'one'

function ProfilePhoto() {
  const camera = useRef<CameraViewRef>(null)
  const [ready, setReady] = useState(false)
  const [photo, setPhoto] = useState<string>()
  return (
    <View style={{ flex: 1 }}>
      <One.iOS.CameraView
        ref={camera}
        style={{ flex: 1 }}
        facing="front"
        codeTypes={[]}
        onStateChange={(state) => setReady(state === 'ready')}
      />
      <Button
        title="Take photo"
        disabled={!ready}
        onPress={async () => {
          const picture = await camera.current?.takePicture({ quality: 0.8 })
          if (picture) setPhoto(picture.uri)
        }}
      />
      {photo ? <Image source={{ uri: photo }} style={{ width: 96, height: 96 }} /> : null}
    </View>
  )
}
```

## How it works

**Starting.** The camera runs only while `active` is true, the view is on
screen, and the app is in the foreground. When all three hold and
permission is granted, the view starts a session on the wide-angle camera
facing the way `facing` says, fills its bounds with the preview, cropping
to keep the aspect ratio, and reports `ready`.

**Scanning.** The requested `codeTypes` are matched against what the camera
can detect. On iOS the metadata output reports each code in every frame it
appears in. On Android, ML Kit analyzes the newest frame at a time, around
1280 by 720, and skips a code identical to the last one delivered. Turning
the view off and on again starts fresh, so the same code is delivered again.

**Taking pictures.** `takePicture` captures a JPEG from the running
session, writes it to the app's cache directory under `Camera/`, and
resolves with its file URI and upright size. The image is turned upright
for the way the phone is held. `flash` applies to each picture; `quality`
runs from 0 to 1 and sets JPEG compression. Ask for `base64` only when you
need the bytes in JavaScript, since it copies the whole image across.

**Torch and zoom.** `enableTorch` keeps the light on while the camera runs.
`zoom` runs from 0, no zoom, to 1, the camera's maximum. Changing `flash`,
`enableTorch`, or `zoom` adjusts the running camera without restarting it.

**Changing props.** A change to `active`, `facing`, or `codeTypes` restarts
the session with the new settings. Duplicate code types are removed before
they reach native code, and an unknown one throws.

**Stopping.** Setting `active` to false, unmounting, or leaving the window
releases the camera. On iOS, going to the background releases it too, and
the view starts again when the app becomes active, which is also when it
notices a permission granted in the system prompt or Settings. On Android,
CameraX follows the activity's lifecycle, pausing in the background and
resuming in the foreground.

**Interruptions on iOS.** When another app or a call takes the camera, the
view reports `inactive` and restarts once the interruption ends. If the
media services reset, it restarts; any other runtime error reports `failed`.

`takePicture` rejects with a `code`:

| Code | Means |
| --- | --- |
| E_CAMERA_NOT_READY | The view is not `ready`: off, no permission, or no camera |
| E_CAMERA_INACTIVE | The camera stopped or restarted before the picture finished |
| E_CAMERA_CAPTURE | The camera failed to produce an image |
| E_CAMERA_UNMOUNTED | The view unmounted first |

`CameraCodeType` is `qr`, `ean13`, `ean8`, `upce`, `code128`, `code39`,
`code93`, `pdf417`, `aztec`, or `dataMatrix`. The view also takes every
React Native view prop, such as `style`.

| State | Means |
| --- | --- |
| inactive | Off, off screen, or interrupted |
| permission-required | Camera permission is not granted |
| unavailable | No camera faces that way |
| ready | Previewing, scanning, and able to take pictures |
| unsupported | None of the code types can be read |
| failed | The camera could not start |

## Platform differences

| | iOS | Android | Web |
| --- | --- | --- | --- |
| Engine | AVFoundation | CameraX and ML Kit | Throws |
| Picture encoding | Camera JPEG as captured | Decoded, turned upright, re-encoded | |
| Repeated code | Every frame | Once in a row | |
| In background | Stops, then restarts | Paused | |
| Permission granted later | Notices on return | Needs a new start | |
| First state when off | Inactive | None | |

## Limits and gotchas

- **Act once, then turn it off.** On iOS a code in view arrives on every
  frame. Set `active` to false in `onCodeScanned`, as the usage example
  does, before acting on the code.
- **Restart after granting on Android.** Android rechecks permission only
  when the view starts. If it reported `permission-required`, set `active`
  to false and back to true once permission is granted.
- **Ask for permission first.** The view reports `permission-required` and
  shows nothing until permission is granted. `getCameraPermissions` reads
  the status without prompting.
- **Native only.** Rendering it on web throws `CameraView requires a native
  build`, so keep it in a native route or behind `One.platform`.
- **Simulators have no camera.** The iOS simulator reports `unavailable`,
  and `takePicture` rejects with `E_CAMERA_NOT_READY`. Test scanning and
  pictures on a device or an Android emulator with an emulated camera.
- **Clean up pictures you keep.** Pictures land in the cache directory,
  which the system may clear. Move one you keep with
  [File System](/native/file-system).
- **Keep the preview on screen.** A view that leaves the window releases
  the camera, so a scanner inside a tab you navigate away from stops until
  you come back.

## Examples

### Show the state while scanning

```tsx
import { useState } from 'react'
import { Text, View } from 'react-native'
import { One } from 'one'

type CameraState = 'inactive' | 'permission-required' | 'unavailable' | 'ready' | 'unsupported' | 'failed'

const messages: Record<CameraState, string> = {
  inactive: 'Camera off',
  'permission-required': 'Allow camera access in Settings',
  unavailable: 'No camera found',
  ready: 'Point at a code',
  unsupported: 'This camera cannot read these codes',
  failed: 'The camera could not start',
}

function ScannerWithStatus({ onCode }: { onCode: (data: string) => void }) {
  const [state, setState] = useState<CameraState>('inactive')
  return (
    <View style={{ flex: 1 }}>
      <One.Android.CameraView style={{ flex: 1 }} onStateChange={setState} onCodeScanned={({ data }) => onCode(data)} />
      <Text>{messages[state]}</Text>
    </View>
  )
}
```

Every state gets a message, so people always know why they see no preview.
`One.Android.CameraView` and `One.iOS.CameraView` are the same component, so
this runs on both platforms.

### Scan product barcodes with the front camera

```tsx
import { useState } from 'react'
import { Button, View } from 'react-native'
import { One } from 'one'

function ProductScanner({ onProduct }: { onProduct: (code: string) => void }) {
  const [facing, setFacing] = useState<'back' | 'front'>('back')
  return (
    <View style={{ flex: 1 }}>
      <One.iOS.CameraView
        style={{ flex: 1 }}
        facing={facing}
        codeTypes={['ean13', 'ean8', 'upce']}
        onCodeScanned={({ type, data }) => onProduct(`${type}:${data}`)}
      />
      <Button title="Flip camera" onPress={() => setFacing(facing === 'back' ? 'front' : 'back')} />
    </View>
  )
}
```

Limiting `codeTypes` to retail barcodes keeps the scanner from firing on
unrelated QR codes nearby. Flipping `facing` restarts the session on the
other camera.
