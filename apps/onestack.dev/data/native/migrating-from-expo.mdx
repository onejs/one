---
title: Migrating from Expo
description: Module-by-module migration notes from Expo packages
---

One's native modules follow Expo's API shapes on purpose, so migration is
mechanical: change the import, apply the rename table on each module page,
and drop the options One does not support. The per-module notes stay on the
module pages; this page indexes them.

| Leaving Expo | Going to One | Notes |
|---|---|---|
| `expo-clipboard` | [Clipboard](/native/clipboard) | `getStringAsync` → `getString`, and likewise for set/has |
| `expo-network` | [Network](/native/network) | `getNetworkStateAsync` → `getState`; enum members become lowercase strings |
| `expo-web-browser` | [Browser](/native/browser) | `openBrowserAsync` → `open`; `WebBrowser` prefixes drop; `ERR_WEB_BROWSER_BLOCKED` → `E_BROWSER_BLOCKED` |
| `expo-image-picker` | [ImagePicker](/native/image-picker) | `launchImageLibraryAsync` → `launchLibrary`; only `mediaTypes` and `selectionLimit` carry over |
| `expo-document-picker` | [DocumentPicker](/native/document-picker) | `getDocumentAsync` → `getDocument`; files are always copied, so `copyToCacheDirectory` drops; `expo-file-system` reads become `fetch(uri)` |
| `react-native-maps` | [Map](/native/map) | Region becomes a camera; marker children become the `markers` array; `onRegionChangeComplete` becomes `onCameraMove` |
| `expo-notifications` | [Notifications](/native/notifications) | Payload shapes match; platform enums are string unions |

Native apps also change build tooling: Expo apps keep Expo prebuild with the
`vxrn/expo-plugin` adapter, while Expo-free apps use `one prebuild` from
`native.app`. See [Build or Run iOS](/docs/guides-ios-native) and
[Ship with EAS](/docs/guides-eas).
