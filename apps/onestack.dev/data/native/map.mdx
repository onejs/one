`One.UI.Map` is one map component for both platforms. On iOS it is the
SwiftUI `Map` from MapKit; on Android it is Google Maps for Compose. You
describe the camera, markers, lines, shapes, and circles as plain props, and
get the same camera and tap events on both. It renders nothing on web.

`One.MapServices` adds place search, typeahead suggestions, and directions
from MapKit on iOS. For MapKit features beyond this shared API, such as Look
Around, use `One.iOS.Map`.

## Usage

```tsx
import { One } from 'one'

const ferry = { latitude: 37.7955, longitude: -122.3937 }

function FerryMap() {
  return (
    <One.UI.Map
      style={{ flex: 1 }}
      cameraPosition={{ coordinates: ferry, zoom: 14 }}
      markers={[{ id: 'ferry', coordinates: ferry, title: 'Ferry Building' }]}
    />
  )
}
```

`cameraPosition` sets where the map starts. People pan and zoom freely after
that, and the camera only moves again when you pass a different value.

Android needs a Google Maps key, set in your app config before prebuild:

```ts
import { one } from 'one/vite'

export default {
  plugins: [
    one({
      native: {
        app: {
          name: 'Places',
          android: {
            applicationId: 'com.example.places',
            googleMapsApiKey: process.env.GOOGLE_MAPS_API_KEY,
          },
        },
      },
    }),
  ],
}
```

iOS needs no key.

## How it works

**Validation.** Before anything reaches native code, the props are checked in
JavaScript. Coordinates outside the valid range, colors that are not
`#rrggbb` or `#rrggbbaa`, negative widths, circles without a positive radius,
empty line or shape coordinates, and duplicate ids within one array all throw
during render with a message naming the bad value. Without `cameraPosition`
the map opens on San Francisco at zoom 12.

**Zoom.** Both platforms use Google's zoom scale, where each step doubles the
scale and the whole world is 256 points wide at zoom 0. Google Maps uses that
scale natively. MapKit has no zoom level, so iOS converts: at zoom z, a view w
points wide shows 360 ÷ 2^z × w ÷ 256 degrees of longitude, and the latitude
span is set from the view's aspect ratio so MapKit has nothing to adjust. The
reported camera runs the same formula backward, so a zoom read from
`onCameraMove` and passed back lands on the same view.

**Camera.** The native view remembers the last camera it was given. When the
props hold the same center and zoom on the next render, it leaves the camera
where the person put it; only a new value moves it. On iOS a change of the
view's width also applies the camera again, since the span depends on it.

**Events.** `onCameraMove` fires once when a gesture ends: on iOS through the
map's camera change callback at the end of the move, and on Android when a
gesture-started move stops. Camera moves you cause from props do not report
on Android. Native code reports a marker tap as the marker's id, and the
component hands you the matching marker object from your props. A tap within
24 points of an iOS pin belongs to the pin, so it never also fires
`onMapClick`; on Android the marker consumes its own tap.

**Android build.** Setting `googleMapsApiKey` makes prebuild write the key
into the app manifest and switch One's Android library to the build that
includes Google Maps for Compose. Without the key, a stub view compiles
instead, so the Maps SDK stays out of the app, and mounting a map stops the
app with a native error that names the missing setting. Changing the key setting needs a new
prebuild and native build. The map view takes its lifecycle from the
activity, so it pauses and resumes with the app.

## Search and directions

`One.MapServices` runs MapKit's local search, search completer, and
directions on iOS. It needs a network connection but no location permission,
since you pass the center yourself. Results use the same coordinate shape as
the map props, so a place can become a marker and a route a polyline.

```ts
import { One } from 'one'

const center = { latitude: 37.7955, longitude: -122.3937 }

async function walkToCoffee() {
  const [place] = await One.MapServices.search('coffee', center, 2000)
  if (!place) return null
  return One.MapServices.directions(center, place.coordinate, 'walking')
}
```

- **search(query, center, radiusMeters = 5000)** returns places for a query.
  The radius must be 100 to 50,000 meters. MapKit treats it as a hint, so
  results can fall outside it. No match resolves to an empty array.
- **autocomplete(query, center, radiusMeters = 5000)** returns suggestions as
  someone types. Each call cancels the one before it.
- **resolveSuggestion(id)** turns a suggestion into a place. Ids come from the
  latest autocomplete result only; the next result replaces them.
- **directions(origin, destination, transport = 'driving')** returns the
  first route MapKit finds, by car or on foot.

Failures reject with an error whose `code` names the cause:

| Code | When |
| --- | --- |
| E_MAP_INPUT | Bad coordinates, radius, empty query, or an old suggestion id |
| E_MAP_SEARCH | Search or suggestion lookup failed |
| E_MAP_AUTOCOMPLETE | The completer failed |
| E_MAP_CANCELED | A newer autocomplete call replaced this one |
| E_MAP_TIMEOUT | Autocomplete gave no result in 20 seconds |
| E_MAP_DIRECTIONS | No route, or routing failed |

On Android only `search` runs natively, through the platform geocoder with
the same input checks and up to 10 results. Autocomplete resolves to an empty
array, and suggestions and directions reject, since Android has no platform
service for them. On web, search and autocomplete resolve to empty arrays and
the other two reject.

## Limits and gotchas

- **Never feed `onCameraMove` into `cameraPosition`.** The camera moves only
  when the prop changes, so writing each gesture's end back into the prop
  makes every pan apply the camera again and fight the next gesture. Keep the
  reported camera in a ref or separate state.
- **Keep camera values stable.** A new object with the same numbers does not
  move the camera, but a new number does, even a tiny one from math on each
  render.
- **Android pins take only the hue.** Google's default pin is tinted by hue,
  so saturation, brightness, and alpha in `tintColor` are dropped there.
- **Android does not open the info window on tap.** The marker's tap handler
  consumes the tap so `onMarkerClick` fires, and that skips Google's default
  info window, so the title does not show on tap.
- **Handle `E_MAP_CANCELED` as you type.** Every autocomplete call cancels the
  pending one, which rejects. Ignore that code rather than showing an error.
- **Web is your own map.** `One.UI.Map` returns nothing on web; render a web
  map library there.
- **Left out on purpose.** Custom marker views and callouts, user location,
  map type and styling, tilt and bearing, gesture toggles, and imperative
  camera control are not part of this API.

## Examples

### Search as you type

```tsx
import { useState } from 'react'
import { Pressable, Text, TextInput, View } from 'react-native'
import { One } from 'one'
const center = { latitude: 37.7955, longitude: -122.3937 }

type Suggestion = { id: string; title: string; subtitle: string }
type Place = Awaited<ReturnType<typeof One.MapServices.resolveSuggestion>>

function PlaceSearch({ onPick }: { onPick: (place: Place) => void }) {
  const [query, setQuery] = useState('')
  const [suggestions, setSuggestions] = useState<Suggestion[]>([])

  async function update(text: string) {
    setQuery(text)
    if (text.trim().length < 2) return setSuggestions([])
    try {
      setSuggestions(await One.MapServices.autocomplete(text, center, 5000))
    } catch (error) {
      if ((error as { code?: string }).code !== 'E_MAP_CANCELED') setSuggestions([])
    }
  }

  return (
    <View>
      <TextInput value={query} onChangeText={update} placeholder="Search places" />
      {suggestions.map((item) => (
        <Pressable key={item.id} onPress={async () => onPick(await One.MapServices.resolveSuggestion(item.id))}>
          <Text>{item.title}</Text>
          <Text>{item.subtitle}</Text>
        </Pressable>
      ))}
    </View>
  )
}
```

A canceled call means a newer one is on its way, so it leaves the list alone.
The ids are only good until the next result, which is why the press resolves
the suggestion straight away.

### Draw a walking route

```tsx
import { useEffect, useState } from 'react'
import { One } from 'one'

const start = { latitude: 37.7955, longitude: -122.3937 }
const end = { latitude: 37.7786, longitude: -122.3893 }

function WalkingRoute() {
  const [path, setPath] = useState<{ latitude: number; longitude: number }[]>([])

  useEffect(() => {
    One.MapServices.directions(start, end, 'walking').then((route) => setPath(route.polyline), () => setPath([]))
  }, [])

  return (
    <One.UI.Map
      style={{ flex: 1 }}
      cameraPosition={{ coordinates: start, zoom: 14 }}
      markers={[
        { id: 'start', coordinates: start, title: 'Start', tintColor: '#34c759' },
        { id: 'end', coordinates: end, title: 'End' },
      ]}
      polylines={path.length ? [{ id: 'route', coordinates: path, color: '#007aff', width: 4 }] : []}
    />
  )
}
```

The route's polyline uses the map's coordinate shape, so it goes straight into
`polylines`. The constant camera means the route can arrive without moving the
map.

### Drop a pin where people tap

```tsx
import { useState } from 'react'
import { One } from 'one'

type Point = { latitude: number; longitude: number }
const city = { coordinates: { latitude: 37.7749, longitude: -122.4194 }, zoom: 12 }

function PinDropper() {
  const [pins, setPins] = useState<Point[]>([])
  return (
    <One.UI.Map
      style={{ flex: 1 }}
      cameraPosition={city}
      markers={pins.map((coordinates, index) => ({ id: String(index), coordinates }))}
      onMapClick={({ coordinates }) => setPins([...pins, coordinates])}
      onMarkerClick={(marker) => setPins(pins.filter((_, index) => String(index) !== marker.id))}
    />
  )
}
```

Taps on the map add a pin and taps on a pin remove it, since a pin tap never
also counts as a map tap. `city` lives at module scope, so adding pins never
moves the camera.

### Look Around on iOS

```tsx
import { useState } from 'react'
import { Button, View } from 'react-native'
import { One } from 'one'

function StreetLevel() {
  const [open, setOpen] = useState(false)
  return (
    <View style={{ flex: 1 }}>
      <One.iOS.Map
        latitude={37.7955}
        longitude={-122.3937}
        markers={[]}
        style={{ flex: 1 }}
        swiftStyle={{
          lookAroundViewer: {
            isPresented: { value: open, onChange: setOpen },
            latitude: 37.7934,
            longitude: -122.395,
          },
        }}
      />
      <Button title="Look Around" onPress={() => setOpen(true)} />
    </View>
  )
}
```

MapKit's Look Around needs iOS 17 and a network connection. The viewer asks
MapKit for a scene at the coordinate; when there is none, or the request
fails, it calls `onChange(false)`, so `open` goes back to false and the
button works again.
