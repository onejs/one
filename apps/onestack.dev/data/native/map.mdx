title: Map
description: One map on both platforms, MapKit on iOS and Google Maps on Android
---

`One.UI.Map` is one map on both platforms: MapKit on iOS, Google Maps
on Android. It takes a Google-style camera, a marker array, and overlay
arrays; the camera seeds from `cameraPosition` and re-seeds only when its
value changes, while the user pans and zooms freely in between.

```tsx
import { One } from 'one'

<One.UI.Map
  style={{ flex: 1 }}
  cameraPosition={{
    coordinates: { latitude: 37.7955, longitude: -122.3937 },
    zoom: 12,
  }}
  markers={[
    {
      id: 'ferry',
      coordinates: { latitude: 37.7955, longitude: -122.3937 },
      title: 'Ferry Building',
      tintColor: '#ff3b30',
    },
  ]}
  onCameraMove={({ coordinates, zoom }) => recordCamera(coordinates, zoom)}
  onMarkerClick={(marker) => selectPlace(marker.id)}
  onMapClick={({ coordinates }) => dropPin(coordinates)}
/>
```

Props, all optional (an empty map renders the default camera over San
Francisco): `cameraPosition` (`coordinates` plus Google `zoom`),
`markers` (`id`, `coordinates`, `title`, `tintColor`), `polylines`
(`id`, `coordinates`, `color`, `width`), `polygons` (`id`,
`coordinates`, `color`, `lineColor`, `lineWidth`), and `circles` (`id`,
`center`, `radius` in metres, `color`, `lineColor`, `lineWidth`).
Colours are `#rrggbb` or `#rrggbbaa` strings; marker ids must be unique.
`onCameraMove` fires once, when a gesture ends. Never feed it back into
`cameraPosition`: that re-seeds the camera on every move end and fights the
pan. `onMarkerClick` returns the marker object from props, matched by
id. Marker taps never also report as map taps.

Excluded on purpose: custom marker views and callouts, user location,
map type and styling, tilt and bearing, gesture toggles, and imperative
camera refs. Web renders nothing; pair with a web map library there.

Android needs a maps key in the app manifest, or mounting throws:

```ts
one({
  native: {
    app: {
      android: {
        googleMapsApiKey: process.env.GOOGLE_MAPS_API_KEY,
      },
    },
  },
})
```

The Maps SDK compiles into Android builds only when the key is set;
without it the dependency stays out of the APK entirely. iOS needs no
key.

## iOS search and directions

`One.iOS.Map` also supports MapKit Look Around through the generated SwiftUI
`lookAroundViewer` style. Keep `isPresented` controlled; MapKit asks for a scene
at the supplied coordinates and calls `onChange(false)` when the viewer closes
or no scene is available. Look Around needs network access and is available on
iOS 17 or later.

```tsx
const [showLookAround, setShowLookAround] = useState(false)

<One.iOS.Map
  latitude={37.7955}
  longitude={-122.3937}
  markers={[]}
  style={{ height: 240 }}
  swiftStyle={{
    lookAroundViewer: {
      isPresented: { value: showLookAround, onChange: setShowLookAround },
      latitude: 37.7934,
      longitude: -122.3950,
    },
  }}
/>
// Set showLookAround to true from a button to present the viewer.
```

`One.iOS.MapServices` uses MapKit's local search and route service. It needs a
network connection, but no location permission when you provide coordinates.
The map view's marker and polyline props accept coordinates from these results.

```ts
const center = { latitude: 37.7955, longitude: -122.3937 }
const places = await One.iOS.MapServices.search('Ferry Building', center, 3000)
const suggestions = await One.iOS.MapServices.autocomplete('Ferry Bu', center, 3000)
const selected = suggestions[0]
if (selected) {
  const place = await One.iOS.MapServices.resolveSuggestion(selected.id)
  // place has the selected suggestion's name, address, and coordinates.
}
const route = await One.iOS.MapServices.directions(
  center,
  { latitude: 37.7786, longitude: -122.3893 },
  'walking'
)
// route.polyline can be passed to One.UI.Map's polylines coordinates.
```

`search(query, center, radiusMeters = 5000)` returns names, addresses, and
coordinates. Radius must be 100 to 50,000 metres and hints the search region;
MapKit may return results outside that region. `directions(origin, destination,
transport = 'driving')` returns the first route's distance in metres, expected
travel time in seconds, polyline coordinates, and instruction steps. The
transport is `driving` or `walking`. Search can return an empty array. Invalid
input rejects with `E_MAP_INPUT`; service and routing failures reject with
`E_MAP_SEARCH` and `E_MAP_DIRECTIONS`.

`autocomplete(query, center, radiusMeters = 5000)` returns MapKit text
suggestions with an `id`, `title`, and `subtitle`. Pass the selected `id` to
`resolveSuggestion(id)` to get its exact MapKit place. IDs remain valid until
the next successful autocomplete result replaces them. A newer query cancels
an unfinished query, which rejects with `E_MAP_CANCELED`; handle that when
updating suggestions as someone types. Invalid input or an old ID rejects
with `E_MAP_INPUT`. MapKit failures use `E_MAP_AUTOCOMPLETE` or `E_MAP_SEARCH`;
a query that does not finish in 20 seconds uses `E_MAP_TIMEOUT`. See
[Apple's MapKit completion guide](https://developer.apple.com/documentation/mapkit/mklocalsearchcompleter)
for how suggestion fragments are produced.
