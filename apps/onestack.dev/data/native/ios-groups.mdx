`One.iOS` grouping, disclosure, glass, and modifier slot views are SwiftUI's
own: `Group`, `GroupBox`, `ViewThatFits`, `GeometryReader`, `ControlGroup`,
`DisclosureGroup`, `Divider`, `Link`, `LabeledContent`, `Glass`,
`GlassEffectContainer`, `Overlay`, `ViewSlot`, and `SwipeActions`. They group
related rows and controls, adapt to available space, and attach native content
such as overlays, insets, and swipe actions to a view.

Reach for `GroupBox` and `DisclosureGroup` for settings cards, `ControlGroup`
for segmented controls, `Glass` for Liquid Glass surfaces on iOS 26 and
later, and `ViewSlot` when a SwiftUI modifier slot needs native content. Every
view here throws on web and Android.

## Usage

```tsx
import { useState } from 'react'
import { One } from 'one'

export function AdvancedSettings() {
  const [open, setOpen] = useState(false)
  const [debug, setDebug] = useState(false)

  return (
    <One.iOS.DisclosureGroup
      label="Advanced"
      isExpanded={open}
      onIsExpandedChange={setOpen}
    >
      <One.iOS.Toggle label="Debug" isOn={debug} onIsOnChange={setDebug} />
    </One.iOS.DisclosureGroup>
  )
}
```

The group expands natively and reports its height as content opens and closes,
so following siblings move with it. The expansion is controlled: the native
tap proposes, and the state update accepts.

## How it works

Group views compose into the parent's hosting controller like any container,
measuring their SwiftUI content and reporting the height back. Controls inside
them stay interactive: taps in an overlay, a slot, or a swipe action reach
React handlers. `DisclosureGroup` is the only controlled one, with an
expansion flag, change callback, and revision like any controlled value.

Slots and markers follow strict rules checked in JavaScript. `Overlay` takes
at most one `Overlay.Content`, `ViewSlot` takes exactly one
`ViewSlot.Content`, and `SwipeActions` takes at most one `Actions` group per
edge. Unknown slot names and slots newer than the device iOS throw, as do
children that are not SwiftUI views.

## Group

`Group` groups children with no visual effect. Use it to apply modifiers or
structure to several views at once.

```tsx
import { One } from 'one'

function Pair() {
  return (
    <One.iOS.Group>
      <One.iOS.Text text="First" />
      <One.iOS.Text text="Second" />
    </One.iOS.Group>
  )
}
```

## GroupBox

`GroupBox` draws SwiftUI's standard group box around its native children.
`label` is optional; omit it for the unlabeled SwiftUI initializer. The box
measures its content and stretches to its parent's width.

```tsx
function Account() {
  return (
    <One.iOS.GroupBox label="Account">
```

## ViewThatFits

`ViewThatFits` shows SwiftUI's first child that fits the proposed size. It
needs iOS 16 or newer. Children stay in preference order; `axes` controls
which dimensions SwiftUI tests, and when none fits SwiftUI shows the last
child. Give the view a `style.height` when vertical fit should use a finite
height proposal: without it the container measures its chosen child and the
vertical proposal is unbounded.

```tsx
import { One } from 'one'

function AdaptiveAction({ run }: { run: () => void }) {
  return (
    <One.iOS.ViewThatFits axes="horizontal">
      <One.iOS.Button label="Detailed action" onPress={run} />
      <One.iOS.Button label="Action" onPress={run} />
    </One.iOS.ViewThatFits>
  )
}
```

## GeometryReader

`GeometryReader` adapts SwiftUI's content builder to a JavaScript function
receiving a `GeometryProxy`. The native reader mounts first; the builder runs
after SwiftUI reports real geometry and runs again when that geometry
changes. No placeholder geometry is delivered. Its returned content composes
natively. Give the reader an explicit size or `flex: 1`, because it fills the
box it is offered. A non-function child throws.

```tsx
import { One } from 'one'

function Measured() {
  return (
    <One.iOS.GeometryReader style={{ height: 100 }}>
      {(geometry) => <One.iOS.Text text={`wide ${Math.round(geometry.size.width)}`} />}
    </One.iOS.GeometryReader>
  )
}
```

`size` and `safeAreaInsets` come from the native geometry proxy.
`frame('global')` and `frame('local')` adapt SwiftUI's `frame(in:)`; frames
and size are reported separately, so a transformed global frame does not
replace the reader's layout size. Named coordinate spaces throw instead of
returning an unrelated frame. A reader in a scroll view can update while
scrolling, so keep the builder cheap and observe it from an effect when
updating React state outside its native content.

## ControlGroup

## Divider

`Divider` draws a hairline between rows. It takes view props only, holds no
content, and must be inside a native container.

```tsx
import { One } from 'one'

function Split() {
  return (
    <One.iOS.VStack>
      <One.iOS.Text text="Above" />
      <One.iOS.Divider />
      <One.iOS.Text text="Below" />
    </One.iOS.VStack>
  )
}
```

## Glass

`Glass` applies a glass or material effect to its children. Give a standalone
`Glass` a height or a flex parent: the surface fills the box it receives.
Glass effects need iOS 26 or newer; `identity` removes the glass while keeping
the children. `cornerRadius` needs `shape="roundedRectangle"`, and an unset
glass effect defaults to `regular` unless a material is given.

```tsx
import { One } from 'one'

function GlassCard() {
  return (
    <One.iOS.Glass glassEffect="regular" shape="roundedRectangle" cornerRadius={16}>
      <One.iOS.Text text="Now playing" />
    </One.iOS.Glass>
  )
}
```

## GlassEffectContainer

`GlassEffectContainer` groups nearby SwiftUI glass effects so the system can
merge them. It needs iOS 26 or newer. `spacing` is an optional finite number
in points; omit it to keep SwiftUI's own default spacing.

```tsx
import { One } from 'one'

function GlassBar({ add, filter }: { add: () => void; filter: () => void }) {
  return (
    <One.iOS.GlassEffectContainer spacing={12}>
      <One.iOS.HStack spacing={8}>
        <One.iOS.Button label="Add" onPress={add} swiftStyle={{ glassEffect: 'regular' }} />
        <One.iOS.Button label="Filter" onPress={filter} swiftStyle={{ glassEffect: 'regular' }} />
      </One.iOS.HStack>
    </One.iOS.GlassEffectContainer>
  )
}
```

## Overlay, Overlay.Content

`Overlay` layers its children over the views behind it with an `alignment`
from the ZStack alignments. `Overlay.Content` marks the overlay subtree; the
overlay takes at most one. Native controls in that subtree can call their
React handlers. Alignment uses the base view's SwiftUI frame: for a full-size
`bottomTrailing` overlay, give the base a native
`swiftStyle.frameWithWidthAndHeightAndAlignment` frame, since a React Native
`style` on the outer host alone does not enlarge an intrinsic `Text` base.

```tsx
import { One } from 'one'

function Badged({ open }: { open: () => void }) {
  return (
    <One.iOS.Overlay alignment="topTrailing">
      <One.iOS.Label label="Inbox" systemImage="tray" />
      <One.iOS.Overlay.Content>
        <One.iOS.Button label="3" onPress={open} />
      </One.iOS.Overlay.Content>
    </One.iOS.Overlay>
  )
}
```

## ViewSlot, ViewSlot.Content

`ViewSlot` hosts a native view modifier slot: `name` picks the SwiftUI slot
(background, mask, alert, list row background, safe-area insets and bars,
accessibility, and the rest) and `options` carries that slot's parameters.
`ViewSlot.Content` marks the slot subtree, exactly one per slot. Unknown names
and slots newer than the device iOS throw. The slot content can contain
interactive native controls.

```tsx
import { One } from 'one'

function PinnedAction({ continueFlow }: { continueFlow: () => void }) {
  return (
    <One.iOS.ViewSlot name="safeAreaInsetWithVerticalEdge" options={{ edge: 'bottom' }}>
      <One.iOS.Text text="Content" />
      <One.iOS.ViewSlot.Content>
        <One.iOS.Button label="Continue" onPress={continueFlow} />
      </One.iOS.ViewSlot.Content>
    </One.iOS.ViewSlot>
  )
}
```

For a side inset, use `name="safeAreaInsetWithHorizontalEdge"` with
`options={{ edge: 'leading' }}` or `options={{ edge: 'trailing' }}`. On iOS
26 or newer, `safeAreaBarWithVerticalEdge` accepts `options={{ edge: 'top' }}`
or `options={{ edge: 'bottom' }}`, and `safeAreaBarWithHorizontalEdge` accepts
`options={{ edge: 'leading' }}` or `options={{ edge: 'trailing' }}`. Put the
bar's native controls in `ViewSlot.Content`.

## SwipeActions, SwipeActions.Actions

`SwipeActions` wraps a `List` row to add swipe actions.
`SwipeActions.Actions` groups the action buttons with `edge` (`'leading'` or
`'trailing'`) and `allowsFullSwipe`. At most one `Actions` group per edge; a
full swipe runs the first action unless `allowsFullSwipe` is false.

```tsx
import { One } from 'one'

function MessageRow({ pinMessage, archiveMessage }: { pinMessage: () => void; archiveMessage: () => void }) {
  return (
    <One.iOS.List>
      <One.iOS.SwipeActions>
        <One.iOS.Text text="Message" />
        <One.iOS.SwipeActions.Actions edge="leading" allowsFullSwipe={false}>
          <One.iOS.Button label="Pin" onPress={pinMessage} />
        </One.iOS.SwipeActions.Actions>
        <One.iOS.SwipeActions.Actions edge="trailing">
          <One.iOS.Button label="Archive" onPress={archiveMessage} />
        </One.iOS.SwipeActions.Actions>
      </One.iOS.SwipeActions>
    </One.iOS.List>
  )
}
```

## Platform differences

| | iOS | Android | Web |
| --- | --- | --- | --- |
| Renders | SwiftUI groups | Throws | Throws |
| Glass | iOS 26 up | None | None |
| Slots | Native slots | None | None |

## Limits and gotchas

- **Slots take one content marker.** `Overlay` takes at most one
  `Overlay.Content`, `ViewSlot` exactly one `ViewSlot.Content`, and
  `SwipeActions` at most one `Actions` group per edge.
- **`Divider` needs a container.** Rendering one outside a native container
  throws, as does giving it children.
- **Links and labeled rows need content.** A `Link` needs a label or children
  plus a parseable URL; `LabeledContent` needs exactly one of `value` and
  children.
- **New views gate on iOS.** `ViewThatFits` needs iOS 16, glass views iOS 26,
  and every slot name is checked against the device version.
