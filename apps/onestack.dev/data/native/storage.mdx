---
title: Storage
description: Fast synchronous key-value storage on iOS, Android, and web
---

`One.Storage` is the app's key-value store: string keys, string values, every call synchronous, with the same verbs as the web's `localStorage`. Use it for app state, caches, and settings. Use [SecureStore](/native/secure-store) for secrets and [Database](/native/database) for structured or large data.

```tsx
import { One } from 'one'

One.Storage.setItem('theme', 'dark')
const theme = One.Storage.getItem('theme') // 'dark', or null
One.Storage.removeItem('theme')
const keys = One.Storage.getAllKeys() // every key this store holds
```

On iOS and Android a shared C++ engine serves calls over JSI. A process-local
map indexes values in a memory-mapped log in the app's private storage. Writes
append records; when the log fills, it compacts live entries if enough space is
unused, or grows the mapping. Compaction writes a snapshot and renames it over
the old log. The store belongs to one process; app extensions do not share it.

This is ordinary persistent app storage. It provides no encryption or explicit
flush API, and a completed write is not a guarantee against device power loss.

On web the same verbs use `localStorage` under keys reserved for this store, so
`getAllKeys` lists only `One.Storage` entries. Call it from browser code;
localStorage is unavailable during server rendering.

Keys must be non-empty strings. Values must be strings, including the empty string. Invalid input throws at the JavaScript boundary without coercion. Missing reads return `null`; removing a missing key succeeds.
