---
title: App Icon
description: Let people choose a bundled alternate app icon
---

`One.AppIcon` reads and changes the launcher icon. The primary icon and
every alternate must be bundled into the binary; an over-the-air
JavaScript update can never add icon images to an installed app.

On iOS it calls `setAlternateIconName` on the shared application. On
Android it enables one launcher `activity-alias` and disables the rest.
On web support reads false, the current name is empty, and changing it
does nothing.

## Usage

```ts
import { one } from 'one/vite'

export default {
  plugins: [
    one({
      native: {
        app: {
          name: 'MyApp',
          icon: { source: 'assets/icon.svg', backgroundColor: '#154a9c' },
          ios: {
            bundleId: 'com.example.myapp',
            alternateIcons: {
              Blue: { source: 'assets/icon-blue.svg', backgroundColor: '#154a9c' },
              Orange: { source: 'assets/icon-orange.svg', backgroundColor: '#d95918' },
            },
          },
        },
      },
    }),
  ],
}
```

Each source must be square and at least 1024 pixels wide. Prebuild
creates the iOS icon sets and selects them in the Alternate App Icon
Sets build setting. The `alternateIcons` keys are the names passed to
`setIcon`. Rebuild the native app after changing icon configuration.

```tsx
import { One } from 'one'

if (await One.AppIcon.isSupported()) {
  const current = await One.AppIcon.getCurrentName()
  if (current !== 'Orange') await One.AppIcon.setIcon('Orange')
}
```

`getCurrentName` returns the installed icon's name, or undefined for the
primary icon. Passing no name to `setIcon` restores the primary icon.

## How it works

iOS shows a system alert on every icon change, so call `setIcon` from a
user action while the app is active. Repeating the current selection
returns without another alert. An unknown name rejects with an input
error; unavailable switching, an inactive app, concurrent changes, and
system failures each reject with their own code.

On Android, declare launcher aliases in the app manifest. Keep the real
host activity enabled and move its MAIN/LAUNCHER filter to the primary
alias. Each alias targets a small launcher activity that forwards into
the permanent host and finishes before React Native renders, because
Android finishes activities launched through an alias when that alias is
disabled: aliases must never target the React Native host directly.
Exactly one launcher alias defaults enabled; each alternate defaults
disabled. Pass the alternate alias's simple name, such as `Blue`, to
`setIcon`; passing no name restores the manifest's primary alias. The
launcher's empty task affinity plus a new-task flag keeps the host task
rooted at the main activity. `isSupported` requires the primary alias
plus at least one alternate, and `getCurrentName` returns undefined for
the primary icon. Without this alias configuration Android reports
unsupported, and restoring the primary rejects. Rebuild after changing
the manifest or resources.

## Platform differences

| | iOS | Android | Web |
| --- | --- | --- | --- |
| Switch | System alert | Alias swap | No effect |
| Setup | Icon sets | Manifest aliases | None |
| Current | Name or empty | Name or empty | Empty |
| Support | Per device | Per manifest | Never |

## Limits and gotchas

- **Bundle every icon.** Alternates ship in the binary only. A name
  without bundled images rejects at the switch.
- **Call from a tap.** The iOS alert needs an active app and a user
  action. Background switches reject as inactive.
- **One switch at a time.** Concurrent `setIcon` calls reject as busy;
  await each before offering the next.
- **Android aliases forward, never host.** Targeting the React Native
  host directly kills it on the next switch. Keep the tiny launcher.
- **Rebuild after icon changes.** New images, aliases, and manifest
  edits all need a native rebuild, never just a reload.

## Examples

### Offer an icon picker

```tsx
import { useEffect, useState } from 'react'
import { Button } from 'react-native'
import { One } from 'one'

const ICONS = ['Blue', 'Orange'] as const

function IconPicker() {
  const [current, setCurrent] = useState<string | undefined>(undefined)
  const [supported, setSupported] = useState(false)

  useEffect(() => {
    One.AppIcon.isSupported().then(setSupported)
    One.AppIcon.getCurrentName().then(setCurrent)
  }, [])

  if (!supported) return null

  async function pick(name: string | undefined) {
    await One.AppIcon.setIcon(name)
    setCurrent(await One.AppIcon.getCurrentName())
  }

  return (
    <>
      <Button title="Primary" onPress={() => pick(undefined)} />
      {ICONS.map((name) => (
        <Button
          key={name}
          title={`${name}${current === name ? ' (on)' : ''}`}
          onPress={() => pick(name)}
        />
      ))}
    </>
  )
}
```

Support gates the whole picker, and re-reading after each switch keeps
the marked row honest even if the system declines the change.

### Restore the primary on sign-out

```tsx
import { One } from 'one'

async function signOut(clearSession: () => Promise<void>) {
  await clearSession()
  if (await One.AppIcon.isSupported()) {
    await One.AppIcon.setIcon()
  }
}
```

Resetting personalization on sign-out keeps the next account's first
impression stock. The support check keeps web and misconfigured builds
quiet.
