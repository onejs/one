`One.iOS` media, shapes, and empty states are SwiftUI's own: `Image` and
`AsyncImage`, the shape views, `VideoPlayer`, `LivePhotoView`, `WebView`,
`Map` with its MapKit controls, `ContentUnavailableView`, and `EmptyView`.
Shapes fill the box React Native gives them; players and the web view take
commands with revisions; the map and empty states render their content
natively.

Reach for these when media should be drawn by the system: symbols, shapes,
video with transport controls, a Live Photo, embedded web content, or a map.
For bundled, remote, and cross-platform images use
[One.UI.Image](/native/image) instead, and for a cross-platform map with
polylines, polygons, and circles use [One.UI.Map](/native/map). Every view
here throws on web and Android.

## Usage

```tsx
import { One } from 'one'

function Status() {
  return (
    <One.iOS.VStack spacing={8}>
      <One.iOS.Image systemName="wifi" swiftStyle={{ imageScale: 'large' }} />
      <One.iOS.RoundedRectangle fill="blue" cornerRadius={12} style={{ height: 64 }} />
    </One.iOS.VStack>
  )
}
```

The symbol draws at large scale and the shape fills the width Yoga offers at a
fixed height.

Every view also accepts `accessibilityLabel`, `accessibilityHint`,
`accessibilityValue`, `testID`, `style`, `onLayout`, and `swiftStyle`.

## How it works

Media views render through Fabric views hosting their SwiftUI content, like
any control. Symbols and shapes measure from SwiftUI; players, the web view,
and the map fill the box they are given, so give them an explicit size or
flex. Commands run through a command string plus a revision: set the command
and increment the revision for each run, including repeats, and native
acknowledges each revision once.

Video keeps its position when other props change and creates a new player only
when `url` changes. The Live Photo loader reads local Photos data and does
not download an iCloud original. Web content loads once per `url` or `html`
value, while the bridge script and navigation policy are configuration set at
creation.

## Image

`Image` draws an SF Symbol by name, or a remote image from `uri`.

```tsx

function Weather() {
  return (
    <>

        swiftStyle={{ symbolRenderingMode: 'multicolor', imageScale: 'large' }}
      />
      <One.iOS.Image systemName="wifi" variableValue={0.5} />
    </>
  )
}
```

## AsyncImage

`AsyncImage` is SwiftUI's `AsyncImage`. It shows a placeholder while it loads
the image at `url`, then draws the image at its own size. Pass `url=""` to
use the SDK nil URL and keep its default placeholder.

```tsx
import { One } from 'one'

function Logo() {
  return <One.iOS.AsyncImage url="https://reactnative.dev/img/tiny_logo.png" scale={2} />
}
```

<PropsTable
  title="Props"
  source="generated/controlTypes.ts#AsyncImageProps"
  data={[
    { name: 'url', required: true, type: 'string', description: 'The image URL. "" shows only the placeholder.' },
    { name: 'scale', type: 'number', default: '1', description: 'Image pixels per point.' },

/>

On iOS 27, changing only `scale` or setting `url` to nil retains the loaded
image under its current identity, matching SwiftUI. Change the React `key` to
recreate the image with a new scale or show the nil URL placeholder.

This binding exposes `init(url:scale:)`. The SDK's image-content, placeholder,
and phase builders, and the iOS 27 request initializers, are not bound: their
callbacks return generic SwiftUI view values or take `URLRequest`, which the
generated constructor bridge cannot carry.

```tsx
function Badges() {
```

## VideoPlayer

`VideoPlayer` plays a local `file://` or remote video from `url` with AVKit's
native transport controls. `autoplay` starts playback when a URL loads. The
player keeps its position when other props change and creates a new player
only when `url` changes.

```tsx
import { One } from 'one'

function Trailer() {
  return <One.iOS.VideoPlayer url="https://example.com/trailer.mp4" autoplay style={{ height: 220 }} />
}
```

<PropsTable
  title="Props"
  source="generated/controlTypes.ts#VideoPlayerProps"
  data={[
    { name: 'url', type: 'string', default: '""', description: 'A file:// or remote video. A new url makes a new player.' },
    { name: 'autoplay', type: 'boolean', default: 'false', description: 'Plays once the video loads.' },
    { name: 'command', type: '"play" | "pause" | "seek" | ""', default: '""', description: 'A command to run. See below.' },
    { name: 'commandRevision', type: 'number', default: '0', description: 'Increase to run command again.' },
    { name: 'seekToMs', type: 'number', default: '0', description: 'Where a seek goes, in milliseconds.' },
    { name: 'onPlaybackStatus', type: '(state: string, positionMs: number, durationMs: number) => void', description: 'loading, playing, paused, ended, or failed, with the time.' },
  ]}
/>

Set `command` to `play`, `pause`, or `seek` and increment `commandRevision`
for each command, including repeated commands of the same kind. Anything else
throws, as does a command with a zero revision or a revision with no command.
For `seek`, pass a nonnegative `seekToMs`.
`onPlaybackStatus(state, positionMs, durationMs)` reports `loading`,
`playing`, `paused`, `ended`, or `failed` with the current time and duration
in milliseconds; unknown or indefinite duration reports as 0. Status arrives
on state changes, after commands, and about twice per second while playing.
Native transport taps also change the reported status.

```tsx
import { useState } from 'react'
import { Button, View } from 'react-native'
import { One } from 'one'

function ControlledVideo() {
  const [control, setControl] = useState({ command: '' as '' | 'play' | 'pause' | 'seek', revision: 0, seekToMs: 0 })
  const send = (command: 'play' | 'pause' | 'seek', seekToMs = 0) =>
    setControl((previous) => ({ command, seekToMs, revision: previous.revision + 1 }))

  return (
    <View>
      <One.iOS.VideoPlayer
        url="https://example.com/trailer.mp4"
        style={{ height: 220 }}
        command={control.command}
        commandRevision={control.revision}
        seekToMs={control.seekToMs}
        onPlaybackStatus={(state, positionMs, durationMs) => console.log(state, positionMs, durationMs)}
      />
      <Button title="Play" onPress={() => send('play')} />
      <Button title="Pause" onPress={() => send('pause')} />
      <Button title="Skip to 10s" onPress={() => send('seek', 10_000)} />
    </View>
  )
}
```

The player follows the app's audio session. This view does not publish Now
Playing metadata or remote transport callbacks. `One.Audio` manages a
separate player with its own remote commands.

## LivePhotoView

`LivePhotoView` displays and plays a Live Photo already in the Photos
library. Request read access with `One.PhotoLibrary.requestReadPermission()`,
then pass the `identifier` of an asset whose `isLivePhoto` is `true`. Give
the view an explicit size. It loads a nondegraded `PHLivePhoto` and shows its
key photo at `ready`. It does not capture or assemble a still and video pair.

```tsx
import { useState } from 'react'
import { Button, View } from 'react-native'
import { One } from 'one'

function LivePhoto({ assetIdentifier }: { assetIdentifier: string }) {
  const [control, setControl] = useState({ command: '' as '' | 'play' | 'stop', revision: 0 })
  const send = (command: 'play' | 'stop') =>
    setControl((previous) => ({ command, revision: previous.revision + 1 }))

  return (
    <View>
      <One.iOS.LivePhotoView
        assetIdentifier={assetIdentifier}
        style={{ width: 320, height: 240 }}
        command={control.command}
        commandRevision={control.revision}
        onPlaybackState={(state, errorCode) => console.log(state, errorCode)}
      />
      <Button title="Play" onPress={() => send('play')} />
      <Button title="Stop" onPress={() => send('stop')} />
    </View>
  )
}
```

<PropsTable
  title="Props"
  source="generated/controlTypes.ts#LivePhotoViewProps"
  data={[
    { name: 'assetIdentifier', required: true, type: 'string', description: 'The Photos local identifier of a Live Photo.' },
    { name: 'autoplay', type: 'boolean', default: 'false', description: 'Plays once the Live Photo is ready.' },
    { name: 'command', type: '"play" | "stop" | ""', default: '""', description: 'A command to run.' },
    { name: 'commandRevision', type: 'number', default: '0', description: 'Increase to run command again.' },
    { name: 'onPlaybackState', type: '(state: string, errorCode: string) => void', description: 'loading, ready, playing, ended, or failed.' },

`autoplay` starts when the nondegraded Live Photo reaches `ready`. Otherwise,
send `play` or `stop` with an increasing positive `commandRevision`, including
for repeated commands. The event order for a normal full play is `loading`,
`ready`, `playing`, `ended`. `stop` returns to `ready` and shows the key
photo. `onPlaybackState` receives `(state, errorCode)`; `errorCode` is `''`
unless `state` is `failed`.

Failures report `E_LIVE_PHOTO_INPUT` for a blank identifier,
`E_LIVE_PHOTO_PERMISSION` without Photos read access,
`E_LIVE_PHOTO_NOT_FOUND` for an unknown or inaccessible asset,
`E_LIVE_PHOTO_NOT_LIVE` for an ordinary image, or `E_LIVE_PHOTO_LOAD` when
Photos cannot supply the Live Photo. The JavaScript wrapper rejects a blank
identifier before mounting. The loader uses local Photos data and does not
download an iCloud original, so a cloud-only asset may fail with
`E_LIVE_PHOTO_LOAD`.

## WebView

`WebView` embeds web content from `url` or an `html` string, exactly one of
the two. Give the view an explicit height because it fills its React Native
box.

```tsx
import { useState } from 'react'
import { One } from 'one'

function Help({ url }: { url: string }) {
  const [revision, setRevision] = useState(0)

  return (
    <>
      <One.iOS.Button label="Reload" onPress={() => setRevision((r) => r + 1)} />
      <One.iOS.WebView
        url={url}
        command={revision > 0 ? 'reload' : ''}
        commandRevision={revision}
        style={{ height: 400 }}
      />
    </>
  )
}
```

and `""` leaves them unset. Use `html` for markup already in the app:

and increment `commandRevision` for each command, including repeated commands
of the same kind. A command with a zero revision, or a revision with no
command, throws; `evaluate` and `postMessage` need a `commandValue`.
`evaluate` runs `commandValue` as JavaScript; `postMessage` dispatches a
`message` event whose `data` is `commandValue`. The page calls
`window.ReactNativeWebView.postMessage` to reach `onMessage`. `script` runs at
document start but rebuilds the page when it changes, so it is for fixed page
setup rather than repeated calls.

## Map

`Map` is the SwiftUI map. Latitude must sit between -90 and 90, longitude
between -180 and 180, and distance above zero, or the map throws.

```tsx
      longitude={-122.4194}
      distance={2000}
      markers={pins}
      onRegionChange={(latitude, longitude, distance) => console.log(latitude, longitude, distance)}
```

## ContentUnavailableView

`ContentUnavailableView` renders an empty state with action buttons. Give it a
height or `flex: 1`; it fills the area React Native assigns. A React state
update after an action can change the view or replace it.

```tsx
import { One } from 'one'

function NoResults({ reload }: { reload: () => void }) {
  return (
    <One.iOS.ContentUnavailableView
      title="No results"
      systemImage="magnifyingglass"
      description="Try a different search."
      actions={[{ id: 'retry', label: 'Retry' }]}
      onAction={(id) => {
        if (id === 'retry') reload()

    />

}
```

## EmptyView

`EmptyView` renders nothing. It is a placeholder where SwiftUI expects a view,
with no props beyond the shared view props. Inside a SwiftUI `HStack`, it adds
no visible element or extra spacing. It has zero visible height. In a React
Native container with `gap`, the gaps on either side still apply to its
position in the child list.

```tsx
import { One } from 'one'

function MaybeBadge({ count }: { count: number }) {
  return (
    <One.iOS.HStack>
      <One.iOS.Text text="Inbox" />
      {count > 0 ? <One.iOS.Text text={`${count}`} /> : <One.iOS.EmptyView />}
    </One.iOS.HStack>
  )
}
```

## Limits and gotchas

- **Commands need revisions.** A command with a zero revision, or a revision
  with no command, throws. Increment the revision for every run, including
  repeats.
- **WebView takes one source.** Exactly one of `url` and `html`; both or
  neither throws.
- **Map bounds are checked.** Latitude, longitude, and a positive distance are
  validated at render, and only the three MapKit controls may nest under a
  map.
- **New shapes gate on iOS.** `ConcentricRectangle` needs iOS 26; other
  shapes render on any supported version.
