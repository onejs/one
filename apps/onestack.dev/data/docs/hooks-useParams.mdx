---
title: useParams
---

Returns URL parameters for the focused route as a plain JS object with strings, including dynamic segments and query string values (aka. search parameters). For typed, schema-validated query string values, use `useSearchParams` instead.

On native, this hook reads the mounted screen's own route parameters, including inherited layout parameters. Retained screens keep their own dynamic values when another screen becomes active. On web, dynamic parameters follow the current URL. Use `useActiveParams` to read the active route globally.

## Basic Usage

```tsx
import { useParams } from 'one'

// Route: app/posts/[id].tsx
// URL: /posts/123?sort=date

export default function PostPage() {
  const { id, sort } = useParams()
  // id = '123', sort = 'date'

  return <Text>Post {id}, sorted by {sort}</Text>
}
```

## TypeScript

### Using `createRoute` (Recommended)

The best way to get fully typed params is with the `createRoute` helper:

```tsx
import { createRoute } from 'one'

const route = createRoute<'/posts/[id]'>()

export default function PostPage() {
  const { id } = route.useParams()
  // id is automatically typed as string!

  return <Text>Post {id}</Text>
}
```

Enable auto-generation in your vite config to have this inserted automatically:

```tsx
// vite.config.ts
one({
  router: {
    experimental: {
      typedRoutesGeneration: 'runtime', // auto-inserts createRoute
    },
  },
})
```

See [Typed Routes](/docs/routing-typed-routes) for full setup details.

### Manual Typing

You can also type params manually:

```tsx
export default function PostPage() {
  const { id, sort } = useParams<{
    id: string
    sort?: 'date' | 'title'
  }>()

  return <Text>Post {id}</Text>
}
```

[!TIP]
While you can type query string parameters (like `sort?` above) manually here, it is generally recommended to use `useSearchParams` for query state instead of `useParams`. Passing a validation schema to `useSearchParams` enforces runtime safety and provides automatic end-to-end type inference across your entire application—including your `<Link>` components.


## Catch-All Routes

For catch-all routes like `[...slug].tsx`, params are returned as arrays:

```tsx
// Route: app/docs/[...slug].tsx
// URL: /docs/api/hooks/useParams

export default function DocsPage() {
  const { slug } = useParams<{ slug: string[] }>()
  // slug = ['api', 'hooks', 'useParams']

  return <Text>{slug.join(' / ')}</Text>
}
```

## URL Decoding

Parameters are automatically URL-decoded:

```tsx
// URL: /search?q=hello%20world
const { q } = useParams()
// q = 'hello world' (decoded)
```

## useParams vs useActiveParams

| Hook | Updates when... | Best for |
|------|----------------|----------|
| `useParams` | Route is focused | Most components |
| `useActiveParams` | Any route changes | Analytics, global UI |

In a stack navigator, if you push a new screen, `useParams` in the previous screen won't update. Use [useActiveParams](/docs/hooks-useActiveParams) if you need global parameter updates.
