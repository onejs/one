---
title: Native Setup
description: Install One Native and generate its iOS and Android projects
---

One Native is included in the `one` package. There is no separate native UI
package to install. One v2 uses React 19.3.0 and React Native 0.88;
the current examples use 0.88.0. Native components require the New Architecture. The
[installation guide](/docs/installation) lists the full dependency set,
including screens, Worklets, and Liquid Glass.
The iOS deployment floor is 17. See the
[platform notes](/docs/native-platforms) for feature-specific requirements.

For a new app, start with:

```bash
npx one
```

For an existing One app, update `one` to v2 and align its React, React
Native, and React Navigation peers. Use your package manager to inspect the
installed package's peer dependencies. The navigation peers are 8 alpha
versions, so keep their versions aligned.

## Configure the app

Configure the application through `native.app` in `vite.config.ts`:

```ts
import { one } from 'one/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [
    one({
      native: {
        app: {
          name: 'MyApp',
          ios: {
            bundleId: 'com.example.myapp',
            deploymentTarget: '17.0',
          },
          android: {
            applicationId: 'com.example.myapp',
          },
        },
      },
    }),
  ],
})
```

Add `react-native.config.cjs` at the app root:

```js
module.exports = require('one/react-native-config')
```

For an existing app, install the community native template as a development
dependency. One supplies the CLI and platform build tools:

```bash
npm install --save-dev @react-native-community/template@0.88.0
```

Then generate the projects from the app directory:

```bash
one prebuild
```

One generates `ios/` and `android/` from the React Native community templates.
React Native autolinking includes One's pod, Android module, Fabric components,
and native service dependencies. Run this through the app's scripts or your
package manager's local executable command if `one` is not on your shell PATH.

Use `native.app` for icons, launch screens, fonts, deep links, and permissions.
The [native project guide](/docs/guides-ios-native#one-prebuild) lists the
manifest fields. Give each permission a description of why your app needs it.
For example, `native.app.imagePicker.camera` supplies the camera usage
configuration. Updating native configuration or adding a native dependency
requires generating and rebuilding the native project.

One's native startup installs the ES2023 array methods `toSorted`, `toReversed`,
`toSpliced`, and `with` before app modules load. This includes Hermes releases
whose built-in array methods are incomplete. Apps use the standard methods
directly; dependency code and app startup need no separate polyfill setup.

Apps that keep Expo prebuild follow [Coming from Expo](/native/migrating-to-one#keeping-expo-prebuild).

## Config plugins

Libraries that ship an Expo config plugin, such as Hot Updater, Stripe or
Mapbox, list it in `native.app.plugins` in the form `app.json` uses: a
package name or a path to a local plugin file, alone or with options.

```ts
native: {
  app: {
    name: 'MyApp',
    ios: { bundleId: 'com.example.myapp' },
    android: { applicationId: 'com.example.myapp' },
    plugins: [
      ['@hot-updater/expo', { channel: 'production' }],
      '@react-native-firebase/app',
      './plugins/with-firebase-configure.cjs',
    ],
  },
},
```

`one prebuild` runs them with Expo's mod compiler after its own edits and
before `pod install`. Plugins import `expo/config-plugins` or
`@expo/config-plugins`; One provides both, so the app does not install
`expo`. A plugin that needs anything else from `expo` belongs on
[Expo prebuild](/native/migrating-to-one#keeping-expo-prebuild).

One's generated files differ from Expo's template, so a plugin can miss the
line it edits. Where Expo prints a warning and continues, `one prebuild`
fails and names the plugin. It also fails when a plugin:

- removes or rewrites code One generates
- changes an Info.plist or entitlements value that `native.app` set, rather
  than adding its own
- requests a permission listed in `android.blockedPermissions`
- sets the Release bundle URL while `native.app.updates` is set; keep one
  update provider
- writes `Podfile.properties.json` or `Expo.plist`, which only Expo's
  template reads

A local plugin is the app's own place for an edit a library's plugin cannot
make. Firebase's plugin looks for the React Native start call in
`AppDelegate.swift`, and One starts React Native from `SceneDelegate.swift`.
Expo runs a later plugin's edit to the same file first, so this local plugin,
listed after Firebase, adds the call and Firebase applies the rest:

```js
// plugins/with-firebase-configure.cjs
const fs = require('node:fs')
const { withDangerousMod, IOSConfig } = require('expo/config-plugins')

module.exports = (config) =>
  withDangerousMod(config, [
    'ios',
    async (config) => {
      const { path } = IOSConfig.Paths.getAppDelegate(config.modRequest.projectRoot)
      const source = fs.readFileSync(path, 'utf8')
      fs.writeFileSync(
        path,
        source.replace(
          'let delegate = ReactNativeDelegate()',
          'FirebaseApp.configure()\n    let delegate = ReactNativeDelegate()'
        )
      )
      return config
    },
  ])
```

Plugins run on every prebuild against freshly generated projects, so the
output is the same each time. Values `native.app` models, such as the bundle
id, version, Info.plist keys and permissions, stay in `native.app`.

## Run the app

Start One's development server in one terminal:

```bash
one dev
```

Build and launch the generated app in another:

```bash
one run:ios
```

Or use `one run:android`. iOS builds need macOS, Xcode, and CocoaPods. Android
builds need the Android SDK and JDK 17. Run native compilation on your build
machine or CI as appropriate for your project.

One bundles native apps with Rolldown, the same bundler as web.

`ONE_PUBLIC_` variables are exposed to app code; see
[Environment](/docs/environment). Rebuild the native app for native code or
manifest changes, even when JavaScript hot reload is working.

## Add a first native control

Put this in an iOS route, such as `app/settings.ios.tsx`:

```tsx
import { useState } from 'react'
import { One } from 'one'

export default function Settings() {
  const [enabled, setEnabled] = useState(true)

  return (
    <One.iOS.Form style={{ flex: 1 }}>
      <One.iOS.Section title="Notifications">
        <One.iOS.Toggle
          label="Allow notifications"
          isOn={enabled}
          onIsOnChange={setEnabled}
        />
      </One.iOS.Section>
    </One.iOS.Form>
  )
}
```

The callback updates the controlled setting in React state. For shared native
text-input state, use `useNativeState` with [TextInput](/native/text-input).
This sample changes a setting only; requesting notification permission is a separate
[Notifications API](/native/notifications) call.
