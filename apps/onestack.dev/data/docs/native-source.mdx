---
title: Swift and Kotlin
description: Import Swift and Kotlin source files from TypeScript and call them as typed functions and components
---

An app can import its own Swift and Kotlin files. One reads each file's
declarations, writes a TypeScript declaration next to it, and generates the
native glue that `one prebuild` compiles into the app. There is no module
boilerplate, no bridge registration and no codegen step to run by hand.

```tsx
import { Device } from './native/Showcase/Device.swift'

const hash = await Device.sha256('hello')
```

Swift imports run on iOS and Kotlin imports run on Android. Native source
requires a project generated by `one prebuild`; Expo prebuild does not generate
it.

## Swift functions

Put Swift files in a Swift package: any directory under the app with a
`Package.swift`. The directory name names the package, so keep it unique and
different from the app's own name.

```swift
// native/Showcase/Package.swift
// swift-tools-version: 6.2
import PackageDescription

let package = Package(
  name: "Showcase",
  platforms: [.iOS(.v17)],
  targets: [
    .executableTarget(name: "Showcase", path: ".", swiftSettings: [.swiftLanguageMode(.v6)]),
  ]
)
```

A class that conforms to `PeachModule` becomes a named export. Each method that
is not `private` or `fileprivate` becomes an async function:

```swift
// native/Showcase/Device.swift
import CryptoKit
import UIKit

@MainActor final class Device: PeachModule {
  init() {}

  func info() -> [String: String] {
    ["model": UIDevice.current.model, "system": UIDevice.current.systemVersion]
  }

  func sha256(_ text: String) -> String {
    SHA256.hash(data: Data(text.utf8)).map { String(format: "%02x", $0) }.joined()
  }
}
```

```ts
import { Device } from './native/Showcase/Device.swift'

await Device.info() // Promise<Record<string, string>>
await Device.sha256('hello') // Promise<string>
```

Methods may be `async` and may `throw`; a thrown error rejects the promise.
The package's sources may import Apple frameworks. SwiftPM package
dependencies are not supported; add native libraries as React Native
dependencies instead.

## Swift views

The package's `@main` type is the default export of its file when it conforms
to `PeachPackage`. The element's props arrive as `JSON`:

```swift
// native/Showcase/Level.swift
import SwiftUI

@main struct Level: PeachPackage {
  func view(props: JSON) -> some View {
    Gauge(value: props["value"]?.doubleValue ?? 0) { Text("Level") }
      .gaugeStyle(.accessoryCircularCapacity)
  }
}
```

```tsx
import Level from './native/Showcase/Level.swift'

export function Meter({ value }: { value: number }) {
  return <Level value={value} />
}
```

A package has at most one `@main` type. A whole SwiftUI app
(`@main struct MyApp: App`) imported this way renders its scene's root view and
fills the space it is given.

## Kotlin functions and views

A Kotlin file can sit anywhere in the app outside `android`, `ios`,
`node_modules` and nested packages. An `object` that implements `OneModule`
becomes a named export, and each of its public functions an async function.
`suspend` functions are awaited. A public `@Composable` function with a
capitalized name becomes a React component whose props are its parameters;
function-typed parameters are callbacks.

```kotlin
// native/Device.kt
import android.os.Build
import androidx.compose.material3.Slider
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import dev.onejs.one.source.OneModule
import java.security.MessageDigest

object Device : OneModule {
    fun info(): Map<String, String> =
        mapOf("model" to Build.MODEL, "system" to Build.VERSION.RELEASE)

    fun sha256(text: String): String =
        MessageDigest.getInstance("SHA-256")
            .digest(text.toByteArray())
            .joinToString("") { "%02x".format(it) }
}

@Composable
fun Level(value: Double, onChange: (Double) -> Unit, modifier: Modifier = Modifier) {
    Slider(value = value.toFloat(), onValueChange = { onChange(it.toDouble()) }, modifier = modifier)
}
```

```tsx
import { Device, Level } from './native/Device.kt'

<Level value={value} onChange={setValue} />
```

A composable's `Modifier` parameter must default to `Modifier`; One supplies
it. Other parameters may only default to `null`, which makes the prop optional.
The composable sizes to its content inside the surrounding layout.

## Types

These types cross the boundary as JSON:

| Swift | Kotlin | TypeScript |
| --- | --- | --- |
| `String` | `String` | `string` |
| `Bool` | `Boolean` | `boolean` |
| `Double`, `Float`, `Int` | `Double`, `Float`, `Int`, `Long` | `number` |
| `[T]` | `List<T>` | `T[]` |
| `[String: T]` | `Map<String, T>` | `Record<string, T>` |
| `T?` | `T?` | `T \| null` |
| `Void` | `Unit` | `void` |

Integer arguments must be whole numbers in range, and `Long` results must fit
in JavaScript's safe integer range. Overloads, generics, default arguments and
static methods are rejected with the file and line.

The declaration sits beside the source as `Device.d.swift.ts` or
`Device.d.kt.ts`. The dev server and `one prebuild` rewrite it whenever they
read the file, and `one typegen` writes all of them. TypeScript reads these
declarations when `allowArbitraryExtensions` is enabled in `tsconfig.json`.

## One import on every platform

A `.swift` import only bundles for iOS and a `.kt` import only for Android. To
use one API everywhere, give the platforms their own entry files and keep the
web implementation in TypeScript:

```
features/native/device.ios.tsx      export { Device } from '../../native/Showcase/Device.swift'
features/native/device.android.ts   export { Device } from '../../native/Device.kt'
features/native/device.tsx          export const Device = { ... }  // web
```

Screens import `features/native/device` and each platform's bundler picks its
file. The starter app created by `npx one@beta` includes this example at the
`/native` route.

## Rebuilds

Native source compiles into the app binary. After adding or editing a Swift or
Kotlin file, run `one prebuild` and rebuild the app. Each generated function
carries a hash of its native contract: if JavaScript reloads against a binary
built from a different contract, calls reject with `E_NATIVE_SOURCE_REBUILD`
instead of reaching mismatched code. OTA updates follow the same rule; see
[native rebuilds and updates](/docs/native-platforms#native-rebuilds-and-updates).
