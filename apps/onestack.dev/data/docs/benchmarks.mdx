and measured again. They do not establish iPhone performance.

## Startup

Process to content ready was 528.62 ms on Hermes and 537.46 ms on Bun.
The first-frame proxy was 500.80 ms and 507.74 ms respectively. The proxy
uses a native display callback; it does not measure pixels appearing on screen.

## Bluesky: historical exploratory samples

Bun reached the recorded thread's final React commit sooner, while Hermes
returned from settings to the home feed sooner and used less memory.
Startup to the first React commit was close. These five pairs ran without a
CPU cap on the same M2 MacBook Air as the microbenchmarks.

Background CPU activity persisted despite quiet admission, with a substantial
load spike during the last pair. All samples are retained. Treat these as
exploratory results pending a controlled repeat and an iPhone comparison.

The thread footprint follows matching host-node counts. The final footprint
after the mismatched profile is excluded. These values include native allocations;
no garbage collection was forced.
The startup metric begins inside the JavaScript bundle, so it excludes native
process launch and runtime initialization and does not measure first pixels.

The long pauses in the original comparison video came partly from the probe:
it waited four seconds without a new startup commit, then two seconds before
an action. Later cases waited 2.5 seconds without a commit, then two seconds
between actions. Those waits are excluded from the reported commit durations.
Both apps were Release builds.

### Bluesky method

Measured on 14 November 2026 using RN 0.81.5 / Expo 54 with the new architecture.
Bun engine 0.1.3 used ahead-of-time compilation with JIT and WebAssembly disabled;
Hermes used optimized bytecode from the same prepared JavaScript bundle.
The native app and dependency changes were shared by both variants.

Five alternating Hermes/Bun pairs ran in three batches of two, two and one.
Each launch started a new process. The simulator, OS caches and signed-in app
data stayed warm, and app data was reused between engines. Native permission
prompts were dismissed before the series. Every launch completed all twenty
actions. Stored responses and images replaced live network responses.
Retained replay logs cover the final launch of each batch for each engine;
all six contain zero misses. Earlier replay logs were overwritten.

The upstream [Bluesky source](https://github.com/bluesky-social/social-app/tree/f3faaa90c74395517538234ce1b6bcb14b864e66)
required the same dependency ports on both engines: MMKV 3.3.3, paste input
2.0.1, UITextView 2.7.1 and a Fabric sheet touch handler. The native Bun adapter
included [the global-pruning fix](https://github.com/onejs/one/commit/ffa53547e).
The downloadable measurements record the prepared bundle and tool hashes.

## Microbenchmark method

Measured on 14 November 2026.

- iPhone 17 Pro simulator, iOS 27.0, on an Apple M2 MacBook Air with 24 GB RAM.
- Release builds, optimized Hermes bytecode and Bun ahead-of-time compilation.
- Bun engine 0.1.1, with both JIT and WebAssembly disabled at simulator launch.
  Device builds disable those features in the runtime.
- One successful smoke per engine preceded ten strict alternating pairs:
  Hermes, Bun, Hermes, Bun. Each launch starts a new process; OS caches remain warm.
- The same application source, native UI, inputs and workload order on both engines.
  The Bun compiler and runtime came from the same engine build.
- A quiet host admission covered the series. All 20 launches reported nominal
  thermal state and low power mode off.
- Compute checksums matched across engines and every launch reached completion.
- Bars show medians, thick lines show the middle 50% of samples, and whiskers
  show the observed minimum and maximum. They are not confidence intervals.
