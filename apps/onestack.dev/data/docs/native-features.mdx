One exposes its native primitives through `One.iOS`, `One.Android`, and `One.UI`.
The platform namespaces follow the names and prop contracts of their native frameworks.
Shared primitives live under `One.UI`.

<Notice theme="yellow">
  These features are experimental. Try them out, but expect API changes.
</Notice>

The native implementation ships with One and links during the native build. No separate
JavaScript package is required.

---

## iOS Color API

Type-safe UIKit semantic colors. These stay as native color values and respond to trait
changes without a React appearance subscription.

```tsx
import { One } from 'one'

<View style={{ backgroundColor: One.iOS.Color.systemBlue }} />
<Text style={{ color: One.iOS.Color.label }} />
```

### iOS Colors

All UIKit semantic colors: `systemBlue`, `systemRed`, `systemGreen`, `label`, `secondaryLabel`, `systemBackground`, `separator`, `systemFill`, `systemGray` through `systemGray6`, and more.

## Zoom Transitions

Native iOS 18+ zoom transitions. The destination screen expands from a source element with a fluid animation.

<Notice>
  Requires iOS 18+. Falls back to standard push transition on older versions.
</Notice>

```tsx
import { One } from 'one'

// source screen — wrap the tappable element
function ListScreen() {
  const router = useRouter()
  return (
    <One.iOS.ZoomTransitionSource identifier="item-1">
      <Pressable onPress={() => router.push('/detail?id=item-1')}>
        <Text>Mountain View</Text>
      </Pressable>
    </One.iOS.ZoomTransitionSource>
  )
}

// destination screen — place the enabler anywhere
function DetailScreen() {
  const { id } = useParams()
  return (
    <View>
      <Stack.Screen options={{ headerShown: false }} />
      <One.iOS.ZoomTransitionEnabler zoomTransitionSourceIdentifier={id} />
      <Text>Detail for {id}</Text>
    </View>
  )
}
```

### Tips

- Set `headerShown: false` on the detail screen to avoid the header overlapping during the zoom animation
- The `identifier` must match between `ZoomTransitionSource` and `ZoomTransitionEnabler`
- Use `One.iOS.ZoomTransitionAlignmentRectDetector` on the destination to align the zoom to a specific element

## Toolbar

Native iOS `UIToolbar` rendered at the bottom of the screen. Supports SF Symbols, badges, and Liquid Glass on iOS 26.

Use React Navigation's `unstable_headerLeftItems` and `unstable_headerRightItems` screen options for header actions. Use `One.iOS.ToolbarHost` directly for a bottom `UIToolbar`; One does not add a second toolbar abstraction.

```tsx
import { One } from 'one'

function MyScreen() {
  return (
    <View style={{ flex: 1 }}>
      <Text>Content</Text>

      <One.iOS.ToolbarHost>
        <One.iOS.ToolbarItem
          identifier="add"
          title="Add"
          systemImageName="plus"
          tintColor={One.iOS.Color.systemBlue}
          onSelected={() => console.log('add tapped')}
        />
        <One.iOS.ToolbarItem identifier="spacer" type="fluidSpacer" />
        <One.iOS.ToolbarItem
          identifier="share"
          title="Share"
          systemImageName="square.and.arrow.up"
          barButtonItemStyle="prominent"
          onSelected={() => console.log('share tapped')}
        />
        <One.iOS.ToolbarItem
          identifier="settings"
          systemImageName="gearshape"
          badgeConfiguration={{ value: '3' }}
          onSelected={() => console.log('settings tapped')}
        />
      </One.iOS.ToolbarHost>
    </View>
  )
}
```

### ToolbarItem Props

| Prop | Type | Description |
|------|------|-------------|
| `identifier` | `string` | Unique ID (required) |
| `title` | `string` | Button title |
| `systemImageName` | `string` | SF Symbol name |
| `type` | `'normal' \| 'fixedSpacer' \| 'fluidSpacer' \| 'searchBar'` | Item type |
| `barButtonItemStyle` | `'plain' \| 'prominent'` | Button style |
| `badgeConfiguration` | `{ value?: string }` | Badge (iOS 26+) |
| `disabled` | `boolean` | Disable the button |
| `hidden` | `boolean` | Hide the button |
| `onSelected` | `() => void` | Tap handler |

## Menu Actions

Native iOS `UIMenu` and `UIAction` for context menus in toolbars.

```tsx
import { One } from 'one'

<One.iOS.MenuAction
  identifier="edit"
  title="Edit"
  icon="pencil"
  onSelected={() => console.log('edit')}
/>

<One.iOS.MenuAction
  identifier="delete"
  title="Delete"
  icon="trash"
  destructive
  onSelected={() => console.log('delete')}
/>
```

## SplitView

Native `UISplitViewController` for iPad multi-column layouts.

<Notice theme="yellow">
  SplitView requires `react-native-screens` gamma mode. Enable it in the One native app manifest:

  ```ts
  one({
    native: {
      app: {
        name: 'MyApp',
        ios: {
          bundleId: 'com.example.myapp',
          screensGamma: true,
        },
        android: { applicationId: 'com.example.myapp' },
      },
    },
  })
  ```

  `one prebuild` adds the Podfile setting before CocoaPods runs. For an existing
  native project that One did not generate, add `ENV['RNS_GAMMA_ENABLED'] ||= '1'`
  to the top of its Podfile. The `SplitView.Column` markers must be direct children of
  `SplitView`; One maps them to the native screen columns and supplies the routed
  detail through `slot`.
</Notice>

```tsx
import { One } from 'one'

function Layout() {
  return (
    <One.iOS.SplitView slot={Detail}>
      <One.iOS.SplitView.Column>
        <SidebarContent />
      </One.iOS.SplitView.Column>
    </One.iOS.SplitView>
  )
}
```

On iPhone, SplitView collapses to a single column automatically.

## Shared Icons

`One.UI.Icon` selects the icon element your app provides for the current platform
and applies a responsive native system color on iOS and Android. Pass a
`One.iOS.Image` and a `One.Android.Icon`; this ensures both native elements can
consume the shared color contract. Your app owns the glyph mapping, availability,
size, variant, directionality, and accessibility label. An icon without a label is
treated as decoration.

```tsx
import { One } from 'one'

const shareIcons = {
  ios: (
    <One.iOS.Image
      systemName="square.and.arrow.up"
      accessibilityLabel="Share"
      swiftStyle={{ fontSize: 20 }}
    />
  ),
  android: <One.Android.Icon name="share" size={20} accessibilityLabel="Share" />,
  web: <ShareIcon color="$color" size={20} />,
}

<One.UI.Icon icons={shareIcons} colorRole="accent" />
<One.UI.Icon icons={shareIcons} color="#E5484D" />
```

`colorRole` accepts `primary`, `secondary`, `tertiary`, `accent`, or `danger`.
The role reaches SwiftUI or Compose unchanged and resolves from the active native
color scheme. A light or dark mode change updates the mounted native icon without a
React appearance subscription. If neither color prop is present, `primary` is the
default. Use `color` for a React Native `ColorValue`, including an iOS dynamic color
in iOS code or a regular color string. `color` and `colorRole` are mutually exclusive.

One does not map these roles on web. When `icons.web` is present, One returns that
React element unchanged so Tamagui or the app can style it. When it is absent, the
component renders nothing on web.

### One.UI.Icon Props

| Prop | Type | Description |
|------|------|-------------|
| `icons` | `{ ios: ReactElement<ImageProps>; android: ReactElement<ComposeIconProps>; web?: ReactElement }` | App-owned platform icons using `One.iOS.Image` and `One.Android.Icon` |
| `colorRole` | `'primary' \| 'secondary' \| 'tertiary' \| 'accent' \| 'danger'` | Responsive native system color |
| `color` | `ColorValue` | Custom color, mutually exclusive with `colorRole` |

## Compose Icons (Android)

Native Material Symbols icons for the Android Compose surface.

```tsx
import { One } from 'one'

<One.Android.Column>
  <One.Android.Icon
    name="star"
    size={24}
    filled
    composeStyle={{ foregroundColor: '#FFC107' }}
  />
  <One.Android.Button label="Next" icon="arrow_forward" iconFilled onPress={() => {}} />
</One.Android.Column>
```

Names are Material Symbols snake_case names from fonts.google.com/icons, such as `star` or `arrow_forward`. There is no mapping to SF Symbols: iOS keeps `systemImage`/`systemName`. Web renders nothing, and unlike the null-returning toolbar and zoom components, the `One.Android` components throw when rendered off Android.

`size` defaults to 24. `filled` picks the bundled filled font instead of outlined. `One.Android.Button` takes a leading icon with `icon` and `iconFilled`; a standalone icon tints with `composeStyle.foregroundColor`, while a Button icon follows the button's content color. Fonts are bundled, so rendering is offline and synchronous. Unknown names throw when the icon renders, and an icon with no `accessibilityLabel` is decorative.

### One.Android.Icon Props

| Prop | Type | Description |
|------|------|-------------|
| `name` | `string` | Material Symbols snake_case name (required) |
| `size` | `number` | Icon size, defaults to 24 |
| `filled` | `boolean` | Use the filled font instead of outlined |

## Platform Support

| Feature | iOS | Android | Web |
|---------|-----|---------|-----|
| Responsive icon colors | One.UI.Icon + UIKit semantic colors | One.UI.Icon + adaptive Material color scheme | app-provided element |
| Zoom Transitions | iOS 18+ | unsupported | unsupported |
| Toolbar | UIToolbar + SF Symbols | unsupported | unsupported |
| Menu Actions | UIMenu / UIAction | unsupported | unsupported |
| SplitView | iPad (gamma required) | routed slot fallback | routed slot fallback |
| Icons | SF Symbols via One.iOS.Image | Material Symbols via One.Android.Icon | unsupported |
| Shared icon selection | One.UI.Icon | One.UI.Icon | app-provided React element |

Unsupported toolbar and zoom components return `null`, so they are safe to keep in
cross-platform component trees. SplitView renders its routed `slot` without native
columns on Android and web.
