One exposes its native primitives through `One.iOS`, `One.Android`, and `One.UI`.
The platform namespaces follow the names and prop contracts of their native frameworks.
Shared primitives live under `One.UI`.

The native primitives ship with One and link during the native build. The image
and SQLite features also need the native packages listed below.

---

## Shared images

`One.UI.Image` displays local and remote images through Nitro Image on iOS and Android.
Use a URL string, a `{ uri }` source, or a bundled React Native image resource.

```tsx
import { One } from 'one'

<One.UI.Image source={{ uri: photoUrl }} resizeMode="cover" style={{ width: 240, height: 160 }} />
```

Apps using remote images install `react-native-nitro-image`,
`react-native-nitro-web-image`, and `react-native-nitro-modules` so the native
image loader is linked into both platforms.

## SQLite

`One.Database` exposes OP SQLite's synchronous and asynchronous database opens
on iOS and Android. Zero apps can use its existing `@rocicorp/zero/op-sqlite`
store provider for the local sync database.

```tsx
import { One } from 'one'

const db = One.Database.open({ name: 'app.sqlite' })
const rows = db.executeSync('SELECT * FROM notes').rows
```

Install `@op-engineering/op-sqlite` in the app's native dependencies.

import { One } from 'one'

### iOS Colors

All UIKit semantic colors: `systemBlue`, `systemRed`, `systemGreen`, `label`, `secondaryLabel`, `systemBackground`, `separator`, `systemFill`, `systemGray` through `systemGray6`, and more.

## Zoom Transitions

Native iOS 18+ zoom transitions. The destination screen expands from a source element with a fluid animation.

<Notice>
  Requires iOS 18+. Falls back to standard push transition on older versions.
</Notice>

```tsx
import { One } from 'one'

// source screen: wrap the tappable element
function ListScreen() {
  const router = useRouter()
  return (
    <One.iOS.ZoomTransitionSource identifier="item-1">
      <Pressable onPress={() => router.push('/detail?id=item-1')}>
        <Text>Mountain View</Text>
      </Pressable>
    </One.iOS.ZoomTransitionSource>
  )
}

// destination screen: place the enabler anywhere
function DetailScreen() {
  const { id } = useParams()
  return (
    <View>
      <Stack.Screen options={{ headerShown: false }} />
      <One.iOS.ZoomTransitionEnabler zoomTransitionSourceIdentifier={id} />
      <Text>Detail for {id}</Text>
    </View>
  )
}
```

### Tips

- Set `headerShown: false` on the detail screen to avoid the header overlapping during the zoom animation
- The `identifier` must match between `ZoomTransitionSource` and `ZoomTransitionEnabler`
- Use `One.iOS.ZoomTransitionAlignmentRectDetector` on the destination to align the zoom to a specific element

## Toolbar

Declarative native toolbar items through `Stack.Toolbar`, in the same compound style as `Stack.Header`. iOS only: leading/trailing slots compile to native header items, and `Stack.Toolbar.Bottom` renders a native `UIToolbar` at the bottom of the screen.

```tsx
import { Stack } from 'one'

<Stack.Screen name="index">
  <Stack.Toolbar>
    <Stack.Toolbar.Leading>
      <Stack.Toolbar.Item title="Edit" systemImageName="pencil" onPress={edit} />
    </Stack.Toolbar.Leading>
    <Stack.Toolbar.Trailing>
      <Stack.Toolbar.Menu title="More" systemImageName="ellipsis.circle">
        <Stack.Toolbar.Item title="Share" onPress={share} />
      </Stack.Toolbar.Menu>
    </Stack.Toolbar.Trailing>
  </Stack.Toolbar>
</Stack.Screen>
```

`Leading`/`Trailing` are the primary direction-aware names (`Left`/`Right` are aliases). Items take `title`, `systemImageName` (SF Symbol), `tintColor` (including dynamic iOS values), `disabled`, `hidden`, `selected`, and the `onPress`/`onSelected` aliases. `sharesBackground` and `hidesSharedBackground` pass through to header items for iOS 26 Liquid Glass.

Options are route-local and dynamic: render a nameless `Stack.Screen` with a `Stack.Toolbar` in route content and its options apply to the current route through `setOptions`, so screen state can drive items without a new API. An explicit slot always wins over incoming options: a slot whose items are all hidden writes an empty array and clears inherited items, while an absent slot preserves them.

### Bottom toolbar

```tsx
// inside screen content, iOS only
<Stack.Toolbar.Bottom hidden={hidden} animated>
  <Stack.Toolbar.Item title="Add" systemImageName="plus" onPress={add} />
</Stack.Toolbar.Bottom>
```

`Stack.Toolbar.Bottom` must mount in screen content where the responder chain reaches the screen view controller; in layout config it warns and is ignored. Bottom items take the same props, including `sharesBackground` and `hidesSharedBackground`.

### Lower-level primitive

`One.iOS.ToolbarHost` with `One.iOS.ToolbarItem` children is the lower-level bottom-`UIToolbar` renderer that `Stack.Toolbar.Bottom` builds on. Reach for it directly only when you need item types the declarative API does not expose (fixed/fluid spacers, search bar, badges).

### ToolbarItem Props

| Prop | Type | Description |
|------|------|-------------|
| `identifier` | `string` | Unique ID (required) |
| `title` | `string` | Button title |
| `systemImageName` | `string` | SF Symbol name |
| `type` | `'normal' \| 'fixedSpacer' \| 'fluidSpacer' \| 'searchBar'` | Item type |
| `barButtonItemStyle` | `'plain' \| 'prominent'` | Button style |
| `badgeConfiguration` | `{ value?: string }` | Badge (iOS 26+) |
| `disabled` | `boolean` | Disable the button |
| `hidden` | `boolean` | Hide the button |
| `onSelected` | `() => void` | Tap handler |

## SplitView

Native `UISplitViewController` for iPad multi-column layouts.

<Notice theme="yellow">
  SplitView requires `react-native-screens` gamma mode. Enable it in the One native app manifest:

  ```ts
  one({
    native: {
      app: {
        name: 'MyApp',
        ios: {
          bundleId: 'com.example.myapp',
          screensGamma: true,
        },
        android: { applicationId: 'com.example.myapp' },
      },
    },
  })
  ```

  `one prebuild` adds the Podfile setting before CocoaPods runs. For an existing
  native project that One did not generate, add `ENV['RNS_GAMMA_ENABLED'] ||= '1'`
  to the top of its Podfile. The `SplitView.Column` markers must be direct children of
  `SplitView`; One maps them to the native screen columns and supplies the routed
  detail through `slot`.
</Notice>

```tsx
import { One } from 'one'

function Layout() {
  return (
    <One.iOS.SplitView slot={Detail}>
      <One.iOS.SplitView.Column>
        <SidebarContent />
      </One.iOS.SplitView.Column>
    </One.iOS.SplitView>
  )
}
```

On iPhone, SplitView collapses to a single column automatically.
`SplitView.Inspector` marks an inspector column the same way `SplitView.Column`
marks a sidebar column.

## Shared Icons

`One.UI.Icon` selects the icon element your app provides for the current platform
and applies a responsive native system color on iOS and Android. Pass a
`One.iOS.Image` and a `One.Android.Icon`; this ensures both native elements can
consume the shared color contract. Your app owns the glyph mapping, availability,
size, variant, directionality, and accessibility label. An icon without a label is
treated as decoration.

```tsx
import { One } from 'one'

const shareIcons = {
  ios: (
    <One.iOS.Image
      systemName="square.and.arrow.up"
      accessibilityLabel="Share"
      swiftStyle={{ fontSize: 20 }}
    />
  ),
  android: <One.Android.Icon name="share" size={20} accessibilityLabel="Share" />,
  web: <ShareIcon color="$color" size={20} />,
}

<One.UI.Icon icons={shareIcons} colorRole="accent" />
<One.UI.Icon icons={shareIcons} color="#E5484D" />
```

`colorRole` accepts `primary`, `secondary`, `tertiary`, `accent`, or `danger`.
The role reaches SwiftUI or Compose unchanged and resolves from the active native
color scheme. A light or dark mode change updates the mounted native icon without a
React appearance subscription. If neither color prop is present, `primary` is the
default. Use `color` for a React Native `ColorValue`, including an iOS dynamic color
in iOS code or a regular color string. `color` and `colorRole` are mutually exclusive.

One does not map these roles on web. When `icons.web` is present, One returns that
React element unchanged so Tamagui or the app can style it. When it is absent, the
component renders nothing on web.

### One.UI.Icon Props

| Prop | Type | Description |
|------|------|-------------|
| `icons` | `{ ios: ReactElement<ImageProps>; android: ReactElement<ComposeIconProps>; web?: ReactElement }` | App-owned platform icons using `One.iOS.Image` and `One.Android.Icon` |
| `colorRole` | `'primary' \| 'secondary' \| 'tertiary' \| 'accent' \| 'danger'` | Responsive native system color |
| `color` | `ColorValue` | Custom color, mutually exclusive with `colorRole` |

## Compose Icons (Android)

Native Material Symbols icons for the Android Compose surface.

```tsx
import { One } from 'one'

<One.Android.Column>
  <One.Android.Icon
    name="star"
    size={24}
    filled
    composeStyle={{ foregroundColor: '#FFC107' }}
  />
  <One.Android.Button label="Next" icon="arrow_forward" iconFilled onPress={() => {}} />
</One.Android.Column>
```

Names are Material Symbols snake_case names from fonts.google.com/icons, such as `star` or `arrow_forward`. There is no mapping to SF Symbols: iOS keeps `systemImage`/`systemName`. Web renders nothing, and unlike the null-returning toolbar and zoom components, the `One.Android` components throw when rendered off Android.

`size` defaults to 24. `filled` picks the bundled filled font instead of outlined. `One.Android.Button` takes a leading icon with `icon` and `iconFilled`; a standalone icon tints with `composeStyle.foregroundColor`, while a Button icon follows the button's content color. Fonts are bundled, so rendering is offline and synchronous. Unknown names throw when the icon renders, and an icon with no `accessibilityLabel` is decorative.

### One.Android.Icon Props

| Prop | Type | Description |
|------|------|-------------|
| `name` | `string` | Material Symbols snake_case name (required) |
| `size` | `number` | Icon size, defaults to 24 |
| `filled` | `boolean` | Use the filled font instead of outlined |

## Shared Effects

Cross-platform effects under `One.UI`. They render through the native
primitives on iOS and Android and throw on web.

`EdgeFade` fades children toward the enabled edges. Each edge takes `true`,
a size in dp, or `{ size, curve, color }`. `curve` is a preset (`smooth`,
`smoother`, `sharp`, `gentle`, `soft`, `linear`), a cubic bezier, or an
alpha stop list. `mode` is `mask` (alpha fade, no color), `overlay` (color
gradient over the children), or `blur` (progressive blur); the mode follows
`color` when omitted, except `blur` which stays explicit. `radius` sets the
corner radius; `style.borderRadius` is ignored.

`Blur` takes `intensity` (0 to 100, default 50) and `tint`. `Mask` takes a
`maskElement` subtree whose opaque pixels show the content.

```tsx
import { One } from 'one'

<One.UI.EdgeFade bottom={64} curve="smooth">
  <LongList />
</One.UI.EdgeFade>

<One.UI.Blur intensity={60} tint="systemMaterial">
  <OverlayCard />
</One.UI.Blur>
```

## Text Input and Native State

`One.UI.useNativeState` creates one observable handle shared between
JavaScript and the bound native views. Pass the handle as `value` to
`One.UI.TextInput`: keystrokes land in every bound view without a React
render. The ref carries `focus`, `blur`, `clear`, `isFocused`, and
`setSelection`.

```tsx
import { One } from 'one'

function NameField() {
  const name = One.UI.useNativeState('')

  return (
    <One.UI.TextInput
      value={name}
      placeholder="Name"
      onSubmitEditing={(text) => save(text)}
    />
  )
}
```

`One.UI.SafeArea` is documented under
[SafeAreaView](/docs/components-SafeAreaView).

## Gradients

Gradients use the React Native 0.87 `backgroundImage` style prop with linear
gradients. No extra component is needed.

```tsx
import { View } from 'react-native'

<View
  style={{
    backgroundImage: [
      {
        type: 'linear-gradient',
        direction: 'to bottom',
        colorStops: [
          { color: 'rgba(0,0,0,1)', positions: ['0%'] },
          { color: 'rgba(0,0,0,0)', positions: ['100%'] },
        ],
      },
    ],
  }}
/>
```

One's own `EdgeFade` overlay mode paints this exact shape, sampling its edge
curve into gradient stops. See `packages/native/src/effects/EdgeFade.native.tsx`
for the prior art. The stable `backgroundImage` key needs React Native 0.87;
0.86 only processes the experimental alias.

## Clipboard

String clipboard through `One.Clipboard`, matching `expo-clipboard`'s string API. Backed by `UIPasteboard` on iOS, `ClipboardManager` on Android, and `navigator.clipboard` on web.

```tsx
import { One } from 'one'

await One.Clipboard.setString('hello')
const text = await One.Clipboard.getString()
const has = await One.Clipboard.hasString()
```

`setString` resolves `true` once the string is on the pasteboard. On web, reads resolve `''` and writes resolve `false` when the browser denies access.

### Migration from expo-clipboard

| expo-clipboard | One |
|---|---|
| `getStringAsync()` | `One.Clipboard.getString()` |
| `setStringAsync(text)` | `One.Clipboard.setString(text)` |
| `hasStringAsync()` | `One.Clipboard.hasString()` |

## Network

Connection state through `One.Network`, matching `expo-network`. Backed by `NWPathMonitor` on iOS, `ConnectivityManager` with a `NetworkCallback` on Android, and `navigator.onLine` with `online`/`offline` events on web.

```tsx
import { One } from 'one'

const state = await One.Network.getState()
// { type: 'wifi', isConnected: true, isInternetReachable: true }

const subscription = One.Network.addStateListener((next) => {
  console.log(next.type)
})
subscription.remove()

const live = One.useNetworkState()
```

`type` is one of `none`, `unknown`, `cellular`, `wifi`, `bluetooth`, `ethernet`, `wimax`, `vpn`, or `other`. On web a live connection reports `unknown`, since browser connection types are unreliable.

The library manifest declares `ACCESS_NETWORK_STATE` (a normal install-time permission, merged into the app automatically).

### Migration from expo-network

| expo-network | One |
|---|---|
| `getNetworkStateAsync()` | `One.Network.getState()` |
| `addNetworkStateListener(fn)` | `One.Network.addStateListener(fn)` |
| `useNetworkState()` | `One.useNetworkState()` |
| `NetworkStateType.WIFI` | `'wifi'` (and likewise for every member) |

## Browser

In-app browser through `One.Browser`, matching `expo-web-browser`'s result shapes. Pages open in `SFSafariViewController` on iOS and Custom Tabs on Android; auth sessions use `ASWebAuthenticationSession` on iOS and Custom Tabs with an app redirect on Android.

```tsx
import { One } from 'one'

const page = await One.Browser.open('https://example.com')
// { type: 'cancel' } once the user closes the sheet
// { type: 'opened' } on Android, which reports no close event

await One.Browser.dismiss()
// { type: 'dismiss' }

const auth = await One.Browser.openAuthSession(
  'https://example.com/login',
  'myapp://auth'
)
// { type: 'success', url: 'myapp://auth?code=…' } on redirect
// { type: 'cancel' } when the user backs out

One.Browser.dismissAuthSession()
```

`open` takes `{ presentationStyle, toolbarColor, controlsColor }` on iOS and `{ browserPackage, toolbarColor, showTitle }` on Android. `openAuthSession` adds `preferEphemeralSession` on iOS. On Android the auth promise settles when the redirect returns to the app (the standard single-task activity delivers it) or with `cancel` when the user closes the tab. The `locked` type reports a second session opened while one is already up. `dismissAuthSession` cancels a pending auth session, whose promise then resolves `dismiss`.

On web, `open` opens a blank-target tab and a blocked popup rejects with code `E_BROWSER_BLOCKED`; `openAuthSession` rejects with `Browser.openAuthSession needs an iOS or Android build`.

### Migration from expo-web-browser

| expo-web-browser | One |
|---|---|
| `openBrowserAsync(url, options?)` | `One.Browser.open(url, options?)` |
| `dismissBrowser()` | `One.Browser.dismiss()` |
| `openAuthSessionAsync(url, redirectUrl?, options?)` | `One.Browser.openAuthSession(url, redirectUrl?, options?)` |
| `dismissAuthSession()` | `One.Browser.dismissAuthSession()` |
| `WebBrowserResult` | `BrowserResult` |
| `WebBrowserResultType` | `BrowserResultType` |
| `WebBrowserPresentationStyle` | `BrowserPresentationStyle` |
| `ERR_WEB_BROWSER_BLOCKED` | `E_BROWSER_BLOCKED` |

## Haptics

Fire-and-forget tactile feedback, exposed as `One.UI.Haptics` (importable from
`@vxrn/native/haptics`). The names follow Apple's feedback generators, not a
hardware spec: `selection` for picking among options, `impact` for physical
commits, `notification` for completion and failure the user cares about.

```tsx
import { One } from 'one'

One.UI.Haptics.selection()
One.UI.Haptics.impact('medium')
One.UI.Haptics.notification('success')
```

The calls are synchronous `void`, not promises: haptics have no meaningful
completion, so awaiting them would only serialize feedback behind bridge
latency. Unknown style or type strings throw a `TypeError` at the JS boundary.
A missing module (old build, web bundler resolving the native file) degrades
to a silent no-op. Web is always a no-op: `navigator.vibrate()` cannot produce
selection/impact/notification feedback.

`impact` accepts `light`, `medium`, `heavy`, `soft`, or `rigid`.
`notification` accepts `success`, `warning`, or `error`. On iOS each maps to
its `UIFeedbackGenerator` directly. On Android the mapping uses
`performHapticFeedback` with no `VIBRATE` permission, so `soft`/`rigid` fold
onto the nearest grade and pre-30 devices fall back: selection uses
`CLOCK_TICK` below API 34, success uses `VIRTUAL_KEY` and error uses
`CONTEXT_CLICK` below API 30 (warning stays `LONG_PRESS`, so warning and
error feel distinct on API 24-29).

Feedback is never the sole success/error signal: pair every call with visual
state. Both platforms honor the system haptics settings without extra code.

## Crypto

Hermes ships no WebCrypto, so One installs `crypto.getRandomValues` and
`crypto.randomUUID` (RFC 4122 v4) on native at startup, backed by
`SecRandomCopyBytes` on iOS and `java.security.SecureRandom` on Android,
both synchronous over the bridge.

```tsx
const id = crypto.randomUUID()
const bytes = crypto.getRandomValues(new Uint8Array(16))
```

Only missing pieces are installed: a runtime that already implements them
keeps its own. There is no fallback to `Math.random`: a missing native
module throws instead of returning weak bytes.

## App info

Installed-binary identity, exposed as `One.AppInfo` (importable from
`@vxrn/native/app-info`). Three fields, read synchronously from the native
constants: `version` is the user-visible marketing version
(`CFBundleShortVersionString` / `versionName`), `build` the binary build
(`CFBundleVersion` / `versionCode`, stringified on both platforms so display
and comparison code stays platform-blind), and `applicationId` the install
identity (`CFBundleIdentifier` / `applicationId`).

```tsx
import { One } from 'one'

One.AppInfo.version // '2.4.6' | null
One.AppInfo.build // '891' | null
One.AppInfo.applicationId // 'dev.app.id' | null
```

The values are a snapshot read once at import and frozen: the binary cannot
change under a running process. `null` means unknown (a host that failed to
stamp, or an old build without the native module), never guessed. On native
the snapshot always describes the installed binary, never bundle-time values:
after an over-the-air update the JavaScript bundle and the binary disagree,
which is exactly when a build comparison must read the binary. On web there
is no installed binary, so the fields come from the build-time manifest
values One injects (`version`, `ios.buildNumber` then `android.versionCode`,
`android.applicationId` then `ios.bundleId`).

Prebuild stamps the binary values from `native.app`: `version` becomes
`MARKETING_VERSION` / `versionName`, `ios.buildNumber` becomes
`CURRENT_PROJECT_VERSION`, and `android.versionCode` becomes `versionCode`.
Missing fields keep the template defaults (`1.0` / `1`), so a store build
must set all three.

## ImagePicker

Uniform imperative image picker. The `expo-image-picker` module API is the reference shape,
so migration is mechanical; this is the small subset One supports.

```tsx
import { One } from 'one'

const picked = await One.ImagePicker.launchLibrary({
  mediaTypes: 'images',
  selectionLimit: 1,
})
if (!picked.canceled) {
  const [first] = picked.assets
  console.log(first.uri, first.width, first.height)
}

const photo = await One.ImagePicker.launchCamera()
```

`launchLibrary` presents the system photo picker: `PHPickerViewController` on iOS,
which needs no permission prompt, and the system photo picker on Android with a documents
fallback on devices without it. `mediaTypes` is `'images'`, `'videos'`, or both, defaulting
to `'images'`. `selectionLimit` is the maximum number of assets, defaulting to `1`; `0` is
unlimited (the system maximum).

`launchCamera` captures one still photo with the system camera. It needs the camera
permission declared in `native.app`:

```ts
one({
  native: {
    app: {
      imagePicker: { camera: 'Take profile photos.' },
      // ...
    },
  },
})
```

`one prebuild` writes the string to `NSCameraUsageDescription` on iOS and declares the
`CAMERA` permission on Android. Without it the call rejects instead of crashing. A denied
permission, a missing camera, and backing out of either call all resolve
`{ canceled: true, assets: null }`; check the permission first when the distinction
matters. Only runtime failures reject, with `E_IMAGE_PICKER_FAILED`.

The camera permission reads without prompting and prompts on request. Neither system
picker needs a grant, so no media library permission calls exist:

```tsx
const current = await One.ImagePicker.getCameraPermissions()
// { status: 'undetermined', granted: false, canAskAgain: true }
const next = await One.ImagePicker.requestCameraPermissions()
```

Picked assets are copied into the app cache and returned as file URIs with `width`, `height`,
and, when the platform provides them, `mimeType`, `fileName`, and `fileSize`. On web the
library opens a file dialog and the camera opens a capture input on mobile browsers, and
both permission calls read granted.

Migrating from `expo-image-picker` is an import change plus this rename:

| Expo | One |
|------|-----|
| `launchImageLibraryAsync` | `launchLibrary` |
| `launchCameraAsync` | `launchCamera` |
| `getCameraPermissionsAsync` | `getCameraPermissions` |
| `requestCameraPermissionsAsync` | `requestCameraPermissions` |

`allowsEditing`, `quality`, `aspect`, and the other Expo options have no equivalent:
`mediaTypes` and `selectionLimit` are the whole options surface.

branches behind platform checks.
